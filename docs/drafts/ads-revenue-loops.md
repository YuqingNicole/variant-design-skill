# 付费广告闭环拆解（草稿）

2026-11-08，代理起草，待维护者确认第 6 节的决定。这里的"付费广告"指**广告主付费，买本站的赞助位**。不包含我们去买量，也不包含联盟分成。

## 1. 大闭环

```
流量 ──▶ 度量 ──▶ 货架 ──▶ 成交 ──▶ 交付 ──▶ 复盘 ──▶ 续约
 ▲                                                    │
 └────────── 数据和口碑回流：更好的流量、更高的价格 ──────┘
```

广告主买的是**可信的、真人的、相关的访问**。这个链条里任何一环断了，后面的环就卖不出去：

- 没有度量，赞助页只能写"不写数字"（现状）。
- 没有货架，赞助页只能写"网站目前还没有赞助位"（现状）。
- 没有交付和复盘，就没有续约。

所以关键路径是**度量 → 货架 → 成交**，GEO 和丝滑度提供流量与转化，完整性提供信任。

## 3. 怎么读下面的表

每个小闭环都要有四样东西，缺一样就不算闭环：**触发 → 动作 → 可观察的结果 → 结果回写到下一次动作**。表里的"完成判据"就是这个结果。

- 轴：**G** = GEO（被找到），**E** = 产品丝滑度（用得顺），**C** = 完整性（可信、不缺块）。
- 依赖写的是编号。"维护者"表示需要账号、付费、公开措辞或法律判断，代理只能起草。
- 没有数字门槛的地方写"待定"，不编。

## 5. 关键路径

不写周数，因为没有数据支撑。按依赖排：

1. **先通水管**：B1 → B2 → B3 → B4 → B5 → B6（有了数字才有后面的一切）。同时做 A2（建 Search Console）和 A1（批准基线）。
2. **再建货架**：C1 → C2 → C3 → C6、C7 → C4 → C5。C3（与编辑隔离）要在任何真实赞助上线前完成。
3. **然后成交**：D1、D2、D3、D5、D6 → D4。
4. **交付复盘**：E1–E4 在第一份合同签下之前就要准备好，否则第一个客户就没有报告。
5. **并行持续做**：A3–A9、F1–F8、H1–H6。它们不挡路，但决定流量和转化。

**不开卖的条件**要由你定（D3 门槛）：至少要有 B6 的口径页、C3 的隔离测试，以及几周的真实数据。我不建议在没有数字时报价。

## 6. 需要维护者定的事

1. **变现形式**：直营赞助位（现有赞助页和规则的方向），还是广告网络（接入第三方脚本，违背 C6 的"不允许第三方脚本"和 B5 的隐私承诺），或两者都做。我建议先做直营。
2. **统计工具**：是否使用 Vercel 的统计，还是别的不用 cookie 的工具。需要先到 Vercel 仪表盘核实当前有没有开启。
3. **版位**：C1 的位置，以及每个位置的数量上限。
4. **开卖门槛**：要多少数据、多久，才开始报价。
5. **收款与主体**：用谁的名义收款，条款由谁审。
6. **询价渠道**：除了 GitHub Issue，用邮箱还是表单。

## 7. 风险

- **信任**：赞助位一旦影响收录、排序或笔记，"互联网上最好的设计灵感"这个定位就失效。C3 的测试和 H4 的说明是底线。
- **AI 引用**：AI 搜索可能把赞助内容当成编辑推荐。赞助内容不进 `llms.txt`、sitemap 和 RSS（C3），并带 `rel="sponsored"`。
- **流量虚高**：AI 爬虫是我们想要的，却不是广告主要的。B3 把两者分开。
- **静态站的限制**：站点是预渲染的，赞助位上线和到期都会碰到"要不要重新构建"的问题（C5）。
- **对标价格**：recent.design 的公开价是它自己流量下的价格，不能直接套用。
