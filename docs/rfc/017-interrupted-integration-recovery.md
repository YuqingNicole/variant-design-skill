# RFC-017：接入和回滚中断恢复

状态：已实现；实际 Codex 43/43 及中断后拒绝冲突/继续恢复流程通过，完整 issue 验收另行跟踪。关联：PRD-003 / Issue #19 I10。

## 问题

接入逐文件原子替换，备份先落盘，但进程中断可能留下新旧目标混合。原回滚只接受全部接入后内容，因此不能继续恢复。普通写入异常后的恢复也可能再次失败。多文件操作不宣称全局原子性或断电持久性。

## 决策

- 新备份增加 `appliedAt: null`；所有目标写入完成并保存完成时间后才返回接入结果。旧备份缺少该字段仍可正常回滚，但不推定为中断接入。
- `recover` 只处理未完成接入，或已经通过严格回滚预检、持久化恢复意图的操作。完成接入仍必须使用严格的 `rollback`，不能借恢复命令绕过后续编辑保护。
- 恢复意图单独保存在 `.integrations/recovery/<id>.json`，绑定完整备份哈希。它在任何恢复写入之前独占写入、读回核对；重复恢复保留相同记录。
- 先校验备份的路径、动作、唯一清单、原始字节哈希和项目根，再整体检查所有变更目标。每个目标必须恰好等于接入前或接入后状态（新建目标的接入前状态是不存在）；其他内容拒绝，写入前报告全部冲突。
- 只恢复仍等于接入后内容的文件；已经恢复的文件保持原样。写入前再次核对当前目标。恢复途中退出后可重复执行相同命令；完成后仅更新现有 `rolledBackAt` 生命周期字段。
- 普通接入异常调用相同恢复逻辑，保留备份和恢复意图。恢复失败时保留诊断和命令，不删除备份或覆盖未知内容。
- 中断接入不能生成交付凭证；恢复不是运行验收。源稿、选择、历史和 staging 不变。
- `.variant-lock` 不自动夺取或删除。进程退出后，先确认无操作仍在运行并检查备份/目标，才移除遗留的空锁目录，再运行恢复命令。

备份和恢复意图先写完整临时文件、flush，再用同目录 hard link 独占发布，读回核对后才允许目标写入；不覆盖已有记录。API 依据：[Node 22 文件系统文档](https://nodejs.org/docs/latest-v22.x/api/fs.html#fslinksyncexistingpath-newpath) 和 [writeFileSync flush](https://nodejs.org/docs/latest-v22.x/api/fs.html#fswritefilesyncfile-data-options)。目标仍逐文件替换，未承诺跨文件原子性；不支持 hard link 的文件系统在写目标之前明确报错。

## 验证门槛

真实 CLI 子进程在首个目标替换后被 SIGKILL，确认实际混合状态、遗留锁、未完成备份；手动排除活进程后恢复并逐字节核对。覆盖全写完但完成标记未落盘、恢复自身被终止、正常回滚途中终止、未知后续编辑、损坏备份、symlink/保护路径、普通 I/O 异常及第二次恢复失败。调用真实 helper，不模拟接入结果。补充真实安装技能的 CLI 使用记录；未运行前不声称体验改善。既有交付凭证回滚和完整检查继续通过。

执行结果与原始失败保留见 [恢复实测](../research/2026-11-05-integration-recovery.md) 和 [源版本审计](../research/2026-11-06-integration-recovery-audit.json)：189 项 Node、38 项浏览器回归及实际四阶段 CLI 流程通过；实际中断后的两次 Agent 操作分别保留后续修改、完成受保护恢复。此结果不替代 #18 的线上/CLI 检查一致性证据或 #25 的外部真人验证。
