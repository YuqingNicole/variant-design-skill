# RFC-016：HTML 交付闭环与逐条失败比较

承接 #18 V8/V9、#19 HTML/Vite 首期矩阵以及 RFC-014/015。当前基于已合并 `98724d9`；不修改商业/账号设置，不宣称 Next 或任意跨根目录接入支持。两个项目的矩阵含义是分别在原生 HTML 和品牌 Vite 项目完成交付，继续遵守 output 必须属于项目根的边界。

## 当前缺口与目标

Vite 已有真实接入/凭证/回滚及原生计划证据；HTML 自动计划只完成生成/修改/撤回。现有比较器将整个 failed check 当一个诊断，日志路径或同项新增错误会使此前存在的诊断一起变成 new-or-changed。目标是在原创 HTML 项目完成真实 Agent 四轮流程，并用实际检查输出区分同项旧/新诊断；有失败的交付仍然 failed。

## 接口与语义

运行观察可在 failed check 提供有界、唯一 `diagnostics: [{id,message,file?,line?,column?}]`。工具负责从实际检查结果提供诊断；不根据关键词、文件名或错误原因猜根因。每条诊断与 check id、实际 tool/environment 一起比较。相同显式诊断的 evidence 日志路径和 check 汇总 reason 不参与诊断身份，但仍完整保存在结果；工具/环境/消息/位置变化仍是 new-or-changed。不带 diagnostics 的旧报告保持整个观察严格比较。比较只说明“此前观察过相同诊断”，不证明同因、环境永远新鲜或已经修复。passed/unverified 不能附 failed diagnostics，缺工具不能伪造诊断。错误仍不能折算通过。

验证计划的已有有界声明式动作执行器以函数导出，供可信宿主在实际交付目标运行同一动作；JSON 不新增命令或代码能力。交付宿主使用真实 before/after 页面和同一计划/视口，显式记录真实基准，不让候选页观察冒充已接入页面。

## HTML 验收场景

新 fixture 复用原创 Progress Review HTML 任务与三轮自动计划，再增加 deliver：Agent 用真实 prepare/apply 接入 index.html 与新建 delivered/ 资源，实际运行项目健康检查、写 before/after 报告、在回滚前封存真实凭证，最后 rollback 并保留历史。原项目故意包含一条预存健康检查失败，不允许改掉或补造通过；返回 candidate-with-recorded-failures。

宿主不执行 Agent 的检查适配代码。直接核对 Agent 清单、备份、日志/报告/凭证与阶段归档后，在独立归档副本中重新准备和接入同一 staging。实际打开原页、三版和比较入口，检查资源、身份、控件、390/1440 视口及接入后的真实 index.html。使用原始只解析不执行的 Node 语法/健康检查器，前后保留旧诊断；再在另一个副本通过真实接入引入 JS 语法错误，要求旧诊断 observed-before、新诊断 new-or-changed、凭证 failed。最后验证真实 target-prepare 冲突、rollback 用户编辑拒绝、原字节恢复和新建资源移除，所有探针只作用于宿主副本。

## 门槛与边界

先补核心比较正反例与旧报告兼容，再跑实际浏览器/原 helper 的多文件接入、失败凭证、冲突/恢复和缺失宿主拒绝；同步全部行为说明与中英文用户文档。随后运行全新项目安装技能的真实 Codex 四轮，独立审计全部阶段/源码/输入/工具/报告/备份/凭证与实际页面；旧 HTML/Vite/原生交付测试不得回退。官方依据：Node vm.Script 的实际语法编译（不运行候选代码）、Playwright 实际网络和页面观察。工具版本以锁定依赖与实际记录为准。

本项不是任意框架、全站无障碍、通用因果诊断或完整人工体验验收。保留其它 backlog、视觉/比较页人工审查、外部用户试用、发行/商业/账号决定。生产合并与现有自动部署沿用维护者的持续授权。
