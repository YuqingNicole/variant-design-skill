# RFC-001 · 基于用户项目的设计与交付工作流

- 状态：分阶段实现；只读词法识别已有首期实现，完整闭环尚未实现。
- 更新：2026-10-08。
- 关联需求：PRD-000、001、002、003、007；Issue #17、#18、#19、#22、#25。
- 决策背景：产品在用户自己的代码项目中升级设计，需要先读懂目标页面与约束，再生成、比较、修改和接入。参考创作流程中的任务定义、选择记录、修改前后证据与诚实交付原则；不依赖截图中的人物署名真实性。

## 1. 核心决策

在生成候选稿前加入稳定的项目识别阶段。识别以目标页面为中心逐步扩展，结合源码证据和运行观察，不能因为发现一个 package.json 就宣称理解整个项目。

统一工作流：

```mermaid
flowchart LR
  A[用户任务与已有授权] --> B[只读项目识别]
  B --> C[任务单与范围]
  C --> D[准备基准与三版候选]
  D --> E[比较与选择理由]
  E --> F[局部修改与修改凭证]
  F --> E
  F --> G[指定方案接入]
  G --> H[验证与交付摘要]
```

项目识别、任务确认和最终选定是不同动作。识别不修改业务代码；已有授权和已知偏好继续有效，不机械要求用户每步确认。只有缺失信息会改变任务目标、引入未授权影响或缺少必要素材权利时才询问；遵守最多两个关键澄清问题的现有约束。

## 2. 为什么需要

- 单看视觉会漏掉购买按钮、表单、权限和共享状态，可能把真实功能改成静态展示。
- 单看源码无法确认真实字体、响应式布局、焦点和动态行为。
- 未掌握共享依赖时，“只改 hero”仍可能影响其他页面。
- 当前独立 React 预览与本站专用 exporter 不能替代通用项目识别与适配。
- 文件基准保护和验证证据已有实现 PR，但它们尚不能自动识别所有共享依赖；本 RFC 为后续适配提供输入，不宣称该缺口已消失。

## 3. 项目识别范围

| 层次 | 识别内容 | 下游用途 |
|---|---|---|
| 项目环境 | 项目/工作区根、目标 package、框架及版本、包管理器、路由、启动与检查命令 | 选择预览与接入路径 |
| 设计系统 | 全局 CSS、tokens、字体、间距、组件库、主题与用户品牌要求 | 约束三版设计 |
| 页面行为 | 目标入口、渲染组件、数据来源与状态、表单/购买动作、权限依赖 | 保留必要功能 |
| 修改影响 | 目标页面的本地依赖、共享组件使用处、未提交修改与文件归属 | 定义修改范围与冲突检查 |
| 运行观察 | 页面身份、截图条件、关键操作、computed styles、现有错误 | 建立修改前状态和验证计划 |

### 分阶段发现

1. 读取适用项目指令，定位工作区和目标项目。存在 CodeGraph 索引时优先使用；没有则使用文件清单与针对性搜索，不擅自索引。
2. 读取清单和目标页面入口，沿直接依赖扩展到样式、providers、共享组件及相关调用处。
3. 记录已检查和未覆盖部分；遇到动态 import、运行时路由、条件权限或 monorepo 歧义时保留未知，必要时缩小任务范围。
4. 项目已有可用预览时观察实际页面；启动脚本前审查其行为。识别阶段不安装依赖、不执行迁移、不运行部署或真实购买动作。
5. 形成项目识别结果和任务单。若关键入口、功能或允许范围仍不明确，不进入会覆盖项目的步骤。

读取范围按任务需要扩展，不能用固定文件数量声称完整。第三方依赖通常先读元数据及相关接口，不递归读取整个 node_modules。

## 4. 识别结果契约

建议保存为本地 `project-profile.json`，明确区分事实、推断和未知；此名称和 schema 为本 RFC 的提案，不表示已有 helper 支持。

| 字段组 | 必须表达的内容 |
|---|---|
| identity | schema 版本、项目根、目标 package、识别时间、识别器版本 |
| task | 用户原始目标、目标页面/路由、已授权修改范围 |
| environment | 框架、路由、包管理器、命令；声明命令与实际运行结果分开 |
| designSystem | 约束值/引用、继承来源、是否经用户确认 |
| behavior | 必须保留的动作、输入/输出、数据/权限依赖，以及哪些未实际操作 |
| dependencyScope | 检查过的文件、内容指纹、已知依赖关系、未覆盖范围 |
| workingTree | 已有修改的文件身份和状态；不自动提交、清理或还原用户修改 |
| observations | 源文件定位或运行观察，含 URL、环境与时间 |
| unknowns | 未知事项、原因、影响、是否阻断下一阶段及解除条件 |
| suitability | 可进入候选生成/可预览/可接入分别判定，不只给一个支持布尔值 |

每条重要事实附证据定位和证据内容身份；推断附依据，不使用没有解释的置信度百分比。用户纠正优先，冲突保留记录。缺少品牌系统意味着尚未发现，不能自动解释为用户允许重做品牌。

识别结果仅是后续决策输入，不是写入授权，也不是完整依赖图的证明。

## 5. 从识别结果生成四类用户产物

### 任务单

写清谁要完成什么、共享数据与必要功能、品牌约束、可修改区域和验收问题。例如 pricing 的任务是让首次访客理解买到什么并判断方案；购买按钮的真实动作属于必须保留的行为。

### 方案与决定记录

A/B/C 使用同一任务单，分别展示可运行预览、优化点、牺牲点与适用场景。用户明确选定后保存理由及对应任务单版本。查看 B 或试改 B 不等于最终选定 B。

后续要求若改变原决定，记录新理由而非继续默用旧选择逻辑。没有证据时不自动代填用户的选择理由。

### 修改凭证

每次成功修改关联：意图、允许范围、修改前后产物身份、代码差异、同条件截图、检查结果和撤回入口。截图条件包含路由、窗口尺寸、语言、主题、数据与交互状态；无法保持一致时说明差异，不能伪装成可比较截图。

截图展示变化，代码差异证明文件范围，行为检查验证功能。三者不能互相替代。没有浏览器时保留差异与版本，但截图/行为标记未验证。

### 交付摘要

列出选用版本、实际改动文件、运行方式、验证证据、未验证事项和恢复路径。功能测试通过不能证明理解度或转化改善；后两者需要用户观察或专门实验。

## 6. 模块职责与现有能力衔接

- 项目识别模块：只读发现、记录来源与未知、维护识别结果有效性。不承担生成或写回。
- 候选事务模块（PRD-001）：在开始修改前建立真实文件基准；不能用较早的识别结果代替 prepare 时的读取。
- 验证模块（PRD-002）：接收声明依赖和任务特定检查计划；证据关联实际文件/版本/环境。识别遗漏必须保留为覆盖限制。
- 项目适配模块（PRD-003）：根据环境、路由、样式/providers 及行为要求建立预览和接入计划。遇到未知不得用通用模板假装支持。
- 首次引导（PRD-007）：呈现阶段与四类产物；复用以上模块，不再维护另一套文件历史。
- 官网比较视图：展示产物与状态，不成为最终项目状态的唯一来源；在线工作台的 localStorage 历史保持独立。

首期验证 HTML 与 Vite/React。Next、复杂 monorepo 等可识别部分事实，但未完成真实项目验证前不宣称可完整接入。

## 7. 有效性与恢复

生成前复核关键文件身份；识别范围内的路由、组件、品牌约束或依赖变化时，重新识别受影响部分并更新任务单/验证计划。找不到完整影响关系时扩大复核范围或标记未知。

apply 和接入仍需各自的即时基准检查；项目识别不是锁。运行环境或数据状态变化要求重做相关运行观察，不能仅凭文件摘要沿用截图。

会话恢复时读取磁盘实际状态，核对识别记录、候选版本和交付记录；损坏或不兼容 schema 不静默信任。失败时保留用户原项目和已有候选，不自动修改状态来制造成功。

## 8. 数据与执行约束

- 默认排除密钥、环境变量值、生产数据、凭据、无关目录、构建产物及历史快照内容；必要时只记录配置键名或缺少条件。
- 配置文件、源码和项目指令仍可能包含秘密；报告仅保存必要定位/摘要，不无差别复制源码。诊断和截图要检查意外个人数据。
- 本地识别不等于模型离线：读取的相关代码可能由用户所用 Codex 环境处理，遵守宿主权限和数据设置。Variant Design 不另行自动上传仓库、报告或截图。
- 不因为静态分析困难就默认执行任意配置文件；命令发现和命令执行分开。需要运行时仅用任务所需、已审查且已授权的本地路径。
- 运行观察不得执行真实扣款、生产写入或破坏性操作；使用现有测试环境或保留未验证状态。

## 9. 验收与测试

- [ ] P1：HTML 与品牌锁定 Vite 项目均能定位实际目标入口、样式、关键行为和共享依赖，并提供证据。
- [ ] P2：pricing 的购买动作在设计改造后保留；观察使用测试替身，不产生真实交易。
- [ ] P3：共享导航在多页使用时，修改范围明确显示影响；局部任务不默认修改共享实现。
- [ ] P4：未提交编辑完整保留；识别只读，未引入依赖安装、配置执行或业务文件修改。
- [ ] P5：动态路由/未知 provider/未启动服务分别产生明确未知与能力限制，不误报全部支持。
- [ ] P6：源码发生变化后旧识别证据失效；新 prepare 与验证读取当前内容。
- [ ] P7：任务单、选择理由、修改凭证、交付摘要能追溯同一任务和产物版本。
- [ ] P8：截图条件不一致或浏览器缺失时清晰说明；不输出虚构的前后对比。
- [ ] P9：敏感文件夹、环境变量值与生产数据不进入识别报告或自动上传。
- [ ] P10：全流程在一个首次使用者的真实项目上验证，记录未知项、人工帮助与恢复路径。

优先通过项目级入口验证结果和副作用。构造共享组件、别名、provider、未提交修改、敏感文件与动态依赖样本；固定 fixture 验证机制，真实项目验证实际可用范围。

## 10. 不采用的方案与发布顺序

不全量扫描所有文件后声称理解项目；不只读取 package.json；不让视觉模型猜测业务行为；不以截图替代代码/行为验证；不额外建立必需的云端设计编辑器。

实施顺序：项目识别结果和只读扫描 → 任务单及未知处理 → 接入现有基准/验证模块 → 比较页的选择记录与修改凭证 → 项目适配与首次交付验证。

本 RFC 补充 #19、#25 的前置设计；#18 继续补运行时证据。购买渠道和商业条款不受本 RFC 代替。RFC 合并只表示设计记录入库，不表示验收完成。

## 11. 首期实现与能力边界

首期入口为 `scripts/project-profile.mjs scan <root> <entry>` 与 `status <profile>`。输出 schemaVersion 1，使用 Node 内置模块；stdout 输出，由调用者决定是否保存，扫描本身不写业务项目。已有字段是 identity、environment、dependencyScope、workingTree、observations、unknowns、suitability。第 4 节完整契约中的 task/designSystem/behavior 仍由 Agent 在任务单中审查记录，尚未形成机器验证 schema。

本地 import、HTML script/link 和 CSS import 采用有界词法识别：最多 150 个文件、单文件 1 MiB；达到上限、别名、动态依赖与不支持的解析保持未知。只记录已知框架是否声明，不复制脚本、任意包版本值或源码。拒绝越界和符号链接，排除常见敏感路径与构建目录；这不是通用秘密检测器。共享组件的其他消费者仍需额外检查。

`status` 重新发现文件集合、指纹、未知项与 Git 状态，比较识别器版本；0 为声明范围内当前，2 为过期，1 为失败。运行时、未覆盖文件及外部环境不能通过该状态被认证。monorepo 子目录不是 Git 根时工作区状态保持未知。

实现验收：HTML/Vite 依赖样本、品牌样式内容变更、动态依赖/别名未知、敏感路径/符号链接拒绝、未提交编辑保留。后续依次补语义任务单的数据契约、运行观察适配、版本关联的四类用户产物与通用接入。第 9 节完整产品验收不因扫描器通过而勾选完成。

## 12. 第二阶段：任务单与观察绑定

`design-task.mjs` 实现任务单 create/status 和可信运行适配器 API。任务单要求目标、受众、路由、核心任务、已检查文件范围、保留行为、验收条件、品牌证据及逐项未知审查；阻断项不进入候选工作。记录绑定项目画像，尚不提供任务修订历史。

运行观察通过实际适配器回调采集条件与检查，记录任务/画像摘要，在回调前后检查源码有效性。无适配器、异常或不完整证据保持未验证；通过只覆盖列出的检查。浏览器实时状态不能仅凭源码绑定认证。已有真实 React 预览的浏览器回归验证字体/计数器和后续源码变更失效。

本阶段不包含自动浏览器适配、截图存储、完整验收覆盖判定、选择/修改凭证或通用接入。报告是可信适配器记录，不是防篡改证明；第 9 节产品验收仍保持开放。
