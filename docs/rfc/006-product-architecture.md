# RFC-006 · 产品架构：开源技能、托管生成与设计系统

- 状态：提案，待维护者确认。§4.1 的“选定后提炼设计系统”已实现并合并（#137），试跑记录见 `docs/research/2026-11-03-design-system-after-pick.md`。付费点（§8 第 1 项）未定。
- 日期：2026-11-03。
- 依据：`docs/research/2026-11-03-design-product-architectures.md`（11 个在线设计产品的公开架构）、`docs/research/2026-11-02-competitor-comparison.md`。
- 关联：PRD-000（付费产品形态，本文修改其“付费交付物”的定义，见 §7）、PRD-004、PRD-005、RFC-001、RFC-002。

## 1. 定位（维护者 2026-11-03 决定）

**Variant Design 把一份需求变成三套完整、可比较的设计方向；用户选定一套后，从它提炼出一套完整的设计系统，之后的页面都建在这套系统上。每一步改动都能撤回。**

- 开源技能永久免费：在用户自己的 agent 里运行（Claude Code、Codex、DeepSeek Harness），模型由用户的 agent 提供。
- 网站提供托管生成：有限的免费额度，超出后付费。
- 托管版产出的项目可以交给本地技能继续做，反过来也可以。

## 2. 和公开竞品比，我们站在哪里

调研结论（详见研究记录）：

| 能力 | 竞品的公开做法 | 我们 |
|---|---|---|
| 多方案 | Subframe 出 2–3 个，Magic Patterns 出 4 个，Stitch 并行；都没有写明结构化比较和明确选定这一步 | A/B/C 共享同一任务和数据，各写明优化什么、牺牲什么；有推荐但不替用户选 |
| 设计系统来源 | 都从导入开始：代码库（Claude Design、v0、Builder）、Figma、网址（Stitch） | 也支持导入（品牌锁定），并且**能从用户选定的生成方向提炼完整系统**。公开页面里没有别家这样做 |
| 约束执行 | v0：来源里查不到就不用；Builder：Strict Mode；Claude Design：出结果前自查 | `delivery-check` 检查品牌锁定；§4.3 补一个 token 一致性检查 |
| 撤销 | 线性版本历史；Claude Design 还没有 | 按方向分别保存修订，一次请求对应一次撤销；有人改过就拒绝撤销；接入后可回滚 |
| 交接 | GitHub PR、MCP | 接入时带回滚；托管版导出给本地技能继续用（§5.5） |
| 免费额度 | 按天计：v0 每天 7 条，Lovable 每天 5 点，Builder 每天 15 点，Figma 每天 150 点 | §5.3 |

结论：在“比较”和“连续性”上我们已经领先，要补的是“设计系统”。设计系统做成“选定后提炼”，这一点公开竞品都没有，应作为主卖点。

托管生成不是我们的优势所在：v0、Lovable、Figma 有专门训练的模型、沙盒和更大的免费额度。我们的优势（读用户仓库、在用户项目里比较、安全接入、可撤回）都发生在本地。所以托管版先当体验入口，不作为主要收入来源，见 §5 和 §8。

## 3. 总体架构

```
 本地技能（开源，MIT，免费）                         托管版（网站，另一个产品）
 ┌───────────────────────────────────────┐          ┌──────────────────────────────────────┐
 │ 用户的 agent：Claude Code/Codex/dsh    │          │ 浏览器工作台                          │
 │ 读用户仓库 · 跑 scripts/*.mjs          │          │ /api/generate · iterate · build      │
 │ 历史、撤销、接入、回滚                 │          │ 一次模型调用，读不到用户仓库          │
 │ 设计系统：design-system.css            │          │ 额度、限流；以后：账号、存储、付费    │
 │          + DESIGN.md + tokens.json     │          │                                      │
 └──────────────────┬────────────────────┘          └──────────────────┬───────────────────┘
                    └──── 只共享：状态格式 v2 · 产品原则 · 项目包（导入/导出） ────┘
```

原则：

1. **托管版是另一个产品，只共享状态格式和产品原则。** 技能的核心是 agent 在用户仓库里读文件、跑脚本；托管版在服务器上调一次模型，读不到用户仓库，代码也不共享。两边共享的是：`.variant-context.json` v2 的状态结构，以及“修改不等于选定”“一次请求一次撤销”“不覆盖用户没看过的改动”“推荐不等于选定”这几条原则。上图底部的“项目包”是两者唯一的接口。
2. **付费买的是服务（托管额度或连续性，见 §8 第 1 项），不是功能。** 开源技能里已有的能力不搬进付费墙（沿用 PRD-000“免费与 Pro 的边界”）。
3. **只承诺测过的东西。** 每一层都有评测或浏览器测试；价格页上的每个数字都来自实测成本。

## 4. 设计系统层

### 4.1 什么时候生成

| 情况 | 行为 |
|---|---|
| 项目没有设计系统，用户 `pick B` | 从 B 提炼完整系统 → 预览 → 停下，等 `ds confirm`（已实现：`skills/variant-design-system/ROUTE.md` Step 1b） |
| 项目已有品牌文件（如 `app/globals.css`） | 品牌文件仍是锁定的那份，不复制也不改；只补品牌没规定的部分（间距、圆角、阴影、动效、组件状态），用 `var(--…)` 引用品牌变量；确认后记入 `designSystem.extensions` |
| 用户直接说 `ds` | 现有流程不变：先生成系统，再 `component` / `compose` |

没有选定的方向不提炼；不替用户确认。这和“推荐不等于选定”一致。

### 4.2 产物：一份系统，三种写法

参考 v0 的 skill、Stitch 的 DESIGN.md 和 Builder 的索引：设计系统既要有确切的值，也要有给代理和人看的使用规则。

| 文件 | 用途 | 格式 |
|---|---|---|
| `variant-output/design-system.css` | 工作格式，页面直接引用 | CSS 变量：原始色板 → 语义色 → 字体层级 → 间距 → 圆角 → 阴影 → 动效 → 层级（现有 Step 1 结构） |
| `variant-output/DESIGN.md` | 给代理和人的规则：每一层为什么这样定、哪些可以做、哪些不行、B 的哪些值被归整了 | 按 Google DESIGN.md 草案的段落顺序（Overview、Colors、Typography、Layout、Elevation & Depth、Shapes、Components、Do's and Don'ts）。该规范是 alpha，只借用结构，不承诺兼容 |
| `variant-output/tokens.json` | 交换格式：导入 Figma 变量或其他工具 | DTCG 2025.10 稳定版。由脚本从 CSS 生成，不手写 |
| `variant-output/design-system-preview.html` | 预览：色板、字号、间距、阴影、动效，以及 B 用到的每个组件的全部状态 | 已实现 |

`tokens.json` 由新脚本 `scripts/ds-export.mjs` 生成（零依赖，有 CLI 和测试）。Figma 只支持部分 DTCG 类型（颜色、px 尺寸、字体、秒为单位的时长、数字），脚本在导出时报告哪些 token 被省略。

### 4.3 约束怎么执行

新增 `scripts/ds-check.mjs`，接入 `delivery-check`：

- 系统确认后，检查每个方向自有文件里的颜色、字号、间距、圆角、阴影：凡是系统里没有的原始值，都报警告并给出最接近的 token。
- 品牌锁定时，扩展文件重新定义品牌变量的，报错误。
- 对比度不合格的语义色组合，报错误（沿用 `color-and-contrast.md` 的阈值）。

这对应 v0 的“查不到就不用”和 Builder 的 Strict Mode，但做成可测试的脚本，而不是只写在提示里。

### 4.4 套用到方向上

`apply ds B` 走现有的 history 流程：prepare → 把 B 的原始值换成 token → apply。整个替换算一次请求，一次撤销就能退回。A、C 不变，也不改变选定状态。

## 5. 托管层

托管版分两步：先做最小的体验入口（§5.1–5.3，不需要数据库和支付），用使用数据决定付费点之后，再做 §5.4 起的完整组件。

### 5.1 现状

网站已有工作台和三个无状态接口 `/api/generate`、`/api/iterate`、`/api/build`：浏览器保存项目，自己应用结果。接口用服务器上的 Anthropic 或 OpenAI 密钥，会替每个访客花钱，所以默认关闭（`PUBLIC_MODEL_ROUTES` 不为 `1`，见 `api/index.mjs`）。托管版就是把它们安全地打开。

### 5.2 第一版（体验入口）

- 打开现有的三个接口，加上：Vercel AI Gateway、BotID、按 IP 和按天的生成次数上限、单次请求的 token 上限。
- 不建账号、不建数据库：项目照旧存在浏览器里。额度先按 IP 和设备计，粗糙但够用；被刷就关掉接口。
- 每次生成记录成本和是否被导出到本地，作为 §8 第 1 项的依据。
- 必须有导出：把项目打成 `variant-output/` 包，交给本地技能继续（§5.6）。体验入口的目的就是把人带到本地技能。

### 5.3 完整版组件（付费点定下来之后）

| 组件 | 方案 | 理由 |
|---|---|---|
| 模型调用 | Vercel AI Gateway，`"provider/model"` 字符串；保留现有 Anthropic/OpenAI 直连作为本地开发选项 | 一个入口切换模型、看用量、设回退；计费口径统一 |
| 计算 | Vercel Functions（Node.js，Fluid Compute）；生成用流式返回 | 默认超时 300 秒，足够一次 A/B/C；不需要 Edge |
| 预览 | 生成结果是静态 HTML 或静态构建，放在带 `sandbox` 属性的 iframe 里，来自单独的预览域名 | 我们的产物本来就能静态打开（`react-preview.mjs --static`）。不需要 v0 那样的虚拟机，也不需要 WebContainers；以后导入用户仓库时再评估 Vercel Sandbox |
| 账号 | 托管版必须登录才能用免费额度；匿名访客只看示例 | 额度要绑定到人，否则免费额度会被刷 |
| 存储 | 通过 Vercel Marketplace 接入 Postgres（项目、方向修订、选定、设计系统、额度流水）；大文件（预览包、截图）放 Vercel Blob（私有） | 和 `.variant-context.json` v2 一一对应，见 §5.4 |
| 防滥用 | Vercel BotID 保护生成接口；按用户和按 IP 限速；单次请求的 token 上限 | 免费额度最大的风险是被刷 |
| 支付与权益 | 按 PRD-005：服务端确认付款，订单和权益分开记录，处理重复通知 | 已有需求，直接沿用 |

### 5.4 额度怎么定

单位：**1 次生成 = 1 组 A/B/C**。修改一个方向、提炼设计系统、导出各算多少，按实测成本折算。参考竞品的做法：手动编辑不扣点，撤销不扣点。

数字先不拍脑袋，按下面的方法定：

1. 在托管接口上用 4 个评测项目各跑 10 次生成，记录每组 A/B/C 的模型成本（AI Gateway 的用量数据）。现有的 Claude Code 评测每次约 $1.8–2，但那是 agent 多轮读文件的成本；托管版一次调用的成本要单独测。
2. 免费额度 = 每月愿意为一个免费用户承担的成本 ÷ 单次成本，并按天封顶（竞品都按天计）。
3. 付费档的额度按同样的方法从价格反推；价格页只写实测得出的数字。

### 5.5 数据模型

和 `.variant-context.json` v2 字段一致，存进表里：

- `project`：brief、taskContract、recommendation、`selectedVariant`、`activeVariant`。
- `direction`：A/B/C，每个有自己的修订链（文件、tokens、comparison、version）。
- `revision`：一次请求一条记录（`request` id），撤销按请求退回。
- `design_system`：`status`（draft / confirmed）、`source`（来自哪个方向）、`file`、`extensions`、版本。
- `credit_ledger`：每次扣点和退点一条记录，失败的生成自动退点。

### 5.6 托管与本地互通

- **导出**：托管项目导出为 `variant-output/` 目录的 zip，包含 `.variant-context.json`、各方向文件、设计系统三件套。解压到用户仓库后，本地技能能直接继续：撤销链、选定和设计系统都还在。这对应 Claude Design 给 Claude Code 的交接包。
- **导入**：本地项目的 `variant-output/` 可以上传到托管版继续，用于分享预览链接。
- **以后**：GitHub PR 交付（v0、Builder 的做法），沿用 `variant-integrate.mjs` 的接入和回滚语义。

### 5.7 隐私与数据

- 第一版不上传用户代码：只发送 brief 和浏览器里的项目文件，不导入仓库。
- 发给模型的内容不在我们这边保存，只记录成本、时长、是否成功和是否导出。
- 以后要导入仓库或保存云端项目时，先写清楚保存什么、保存多久、怎么删除，再上线。

### 5.8 设计质量怎么评估

现有检查只覆盖流程承诺（三版齐全、没替用户选、品牌没被改、质量门），不衡量好不好看。补两样：

- **盲评**：`docs/trials/blind-review.md` 已有流程（技能产出与同一 agent 的直接产出对比），每次大改技能文本后跑一轮，记录到 `docs/research/`。
- **设计系统的可测指标**：对比度是否全部合格、token 数量（间距、字号步数）、页面中未使用系统 token 的原始值个数（`ds-check.mjs`）。

## 6. 分阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 技能：设计系统 | 选定后提炼（已实现）；`DESIGN.md`；`ds-export.mjs`；`ds-check.mjs` 接入 delivery-check；`apply ds B` | 单元测试；`evals/` 新增“生成 → pick → ds confirm → apply ds”两轮 fixture，Claude 和 Codex 各跑通；研究记录 |
| P1 定位文案 | 价格页、`llms.txt`、README 开头、/about：技能免费，托管有限免费，设计系统是主卖点 | 页面之间说法一致；浏览器测试 |
| P2 托管体验入口 | §5.2：AI Gateway、BotID、按 IP 和按天限次、成本记录、项目包导出 | 成本实测记录；滥用测试；PRD-004 的工作台一致性验收；导出的项目在本地技能里能继续改 |
| P3 决定付费点 | 用 P2 的数据回答 §8 第 1 项 | 维护者决定，写进 PRD-000 |
| P4 付费 | 按 P3 的选择：甲做账号、数据库、额度流水和支付；乙做云端历史、分享链接和团队设计系统。支付都走 PRD-005 | PRD-005 E1–E7 |

P0、P1 不依赖账号和支付，现在就能做。P2 只需要维护者同意承担一小笔模型费用并定上限；账号、数据库和支付等 P3 定下来再选。

## 7. 对现有文档的影响

- **PRD-000**：原定义是“付费交付物 = 本地插件发行包，不另建必须登录的设计编辑器”。新定位下付费买的是托管额度和连续性，需要维护者改写 PRD-000 的“产品定义”一节。“开源能力不进付费墙”“只承诺有证据的增量”两条原则保留。
- **价格页**：本地版写着“永久免费、不会被限制”，这句仍然成立。专业版的“托管生成额度”要改成“有限免费额度 + 付费额度”，数字等 §5.3 实测后再写。
- **`llms.txt`**：“there is no hosted service” 要改成“托管生成在早期访问中，有有限免费额度”，等 P2 上线后再改成正式说法。

## 8. 待维护者决定

1. **付费点卖什么。**
   - 甲：托管模型额度（Pro 档的“托管生成额度”）。问题是正面对上 v0、Lovable，且要承担模型成本风险。
   - 乙：连续性，包括云端历史、可分享的预览链接、团队共享的设计系统；生成仍用用户自己的 agent 或订阅（Subframe 已允许用户用自己的 Claude 或 Codex 订阅）。这更贴近我们的优势，成本风险小。
   - 建议：乙。也可以等 P2 有了数据再定。
2. P2 愿意承担的模型费用上限，以及以后免费额度愿意承担的每用户月成本（决定 §5.4 的数字）。
3. 登录方式和支付供应商（P4 的阻断项）。
4. 默认模型：托管版用哪家模型，是否允许用户自带密钥（Subframe 允许用 Claude 或 Codex 订阅）。
5. `DESIGN.md` 是否跟随 Google 草案；如果它改动大，是否改用自己的结构。
6. PRD-000 的改写。

## 9. 不做

- 不做 Figma 式的自由画布编辑器；编辑仍然是“说出要改什么 + 区域选择”（区域点选是 TODO 第 4 节的待定项）。
- 不按生成次数以外的方式锁功能；不加许可证校验到开源技能里。
- 不在没有实测成本之前公布额度数字。
