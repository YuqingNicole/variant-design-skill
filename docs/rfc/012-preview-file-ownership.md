# RFC-012：预览文件归属、重建与安全清理

执行范围：#19 / PRD-003 I4、I9 的既有要求。不是新框架支持、发布许可或完整 #19 验收。基于 PR #158 的原生 Vite 证据继续实现。

## 问题与目标

`build-preview.mjs` 直接覆盖 `_compare.html` 和 React 挂载文件；`react-preview.mjs --static` 递归删除整个 `_static/`。它们不能识别旧文件或用户后续修改。原生适配器目前也只有“记录文件供清理”的文字，没有可执行的归属协议。

目标是让首次生成拒绝已有路径，重建只更新仍与上次收据一致的工具文件，清理只移除本次生成且未被修改/替换的文件。清理不删除目录、不扫描目录后推定归属、不收养旧文件，不影响变体版本、最终选择、生产入口或依赖清单。旧的无收据预览保留，提示选择全新输出路径，不提供 force 或事后收养。

## 契约

新增零依赖 Node 22 helper `scripts/preview-files.mjs`。元数据放在项目 `.variant-work/preview-files/`；所有路径使用 `localFile`，拒绝符号链接、目录目标、特殊文件、硬链接及元数据/历史等受保护路径。

- Bundled builder：`publishPreview(project, group, files)` 接收完整的路径→字节映射。初次只允许不存在的文件；以后读取 group 当前指针和不可覆盖的收据，对所有旧文件检查内容、权限、文件身份，再生成新收据。不同输出目录用不同 group。旧组文件不再需要时只按同样的基准逐文件移除，不递归清空目录。
- 原生适配器：写之前 `preparePreview(project, paths, planFile)`，要求每个目标不存在，并以排他写持久化计划；写完后 `sealPreview(project, planFile)` 固定文件字节、权限及身份，生成不可覆盖的收据。只能封存一次。后续修改使用 publish 的受保护写入，不通过重新封存消除冲突。
- `cleanupPreview(project, receiptFile)` 不执行命令或停进程。先持久化待清理文件的内容备份；逐项重新比对后删除匹配文件，缺失的记 missing，改变/替换/链接的记 conflicts 并保留；未登记文件始终不动。返回完整 removed/missing/conflicts 与备份路径。重复清理不会把新建的同名文件认作旧文件。
- 重建/清理前把操作、旧字节及预期新身份写入唯一的操作记录并回读。普通写入失败只恢复仍是本次写入的文件；后续编辑保留，记录恢复冲突。备份和诊断留存。没有多文件崩溃原子性承诺。

同一项目的 helper 使用排他目录锁协调，锁不自动抢占。外部编辑器不共享锁；操作前和逐项执行前重查，仍不宣称能消除最后一次检查与 OS 操作之间的竞态。文件身份记录用于保留被删除后重新创建的同名同内容文件；不是密码学来源认证。收据和组指针采用内容哈希核验；用户主动伪造整个元数据树不在来源认证承诺内。

Node 22 [文件系统官方文档](https://nodejs.org/docs/latest-v22.x/api/fs.html) 说明排他创建 `wx`、flush 及 check/use 竞态边界；新目标使用排他创建，已有目标只在基准一致后替换，不把存在性检查当作 OS 锁。

## 接入与验证

比较页/挂载脚本一次性准备字节映射再 publish。静态构建先在临时目录完成全部打包，再 publish 完整文件映射；移除 `_static` 的递归删除。返回/打印实际收据和清理命令；结束本次服务进程与清理文件分开说明。

回归覆盖：已有同名文件、合法重建、用户改字节/权限、同名同字节替换、缺失文件、未知文件、旧收据、路径穿越/链接/特殊文件、并发锁、普通写失败的受控恢复、清理中断与重复清理，以及变体与选择状态不变。真实 Chrome 验证静态三版渲染及交互仍可用。安装包包含 helper。真实 CLI dogfood 检查 Agent 是否在创建原生适配前登记路径、能报告收据，并保留后改/旧文件；不能以手写 fixture 代替该门槛。

共享依赖发现、完整交付凭证、#18 自动检查计划及其它 backlog 继续开放。验收记录写入 research 和执行索引；生产与 release 版本不变。
