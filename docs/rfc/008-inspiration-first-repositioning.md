# RFC-008 · 改定位：以设计灵感为主

- 状态：已接受。P1（定位和信息结构）已实施（2026-11-03）。P2 已实现并通过本地回归，截图待维护者审阅；P3 已实现并通过本地验证，待 PR/预览审核。
- 日期：2026-11-03。
- 关联：
  - RFC-003（参考库验证闭环）、RFC-004（首页第一屏，本文取代它的首页结构）、RFC-005（多语言地址）；
  - `docs/design-system.md`；
  - `references/workflow/adjective-translation.md`（P2 用它把"审美上升"拆成可检查的项）。
- 范围：`website/` 的定位、首页、导航、页面地址和预渲染。技能本身不在范围内。

## 1. 决定

维护者 2026-11-03 要求"把定位改成 recent.design 那样，然后交互和审美再上升一大截"。四个选择由维护者确定：

| 问题 | 决定 |
|---|---|
| 首页首屏 | 一行短主张，下面紧跟作品流 |
| Variant Design 技能放哪 | 降为"资源"里的一项；文档、价格、关于、更新记录、实验室在技能入口和页脚里 |
| 作品图片从哪来 | 守住授权：继续只用官方嵌入、作者授权的截图和自己画的分析卡，另加投稿和授权流程 |
| 一句话定位 | "互联网上最好的设计灵感" / "The best design inspiration on the internet" |

### 和 recent.design 的区别

参考的是公开页面的定位和信息结构，不复制它的界面、文案细节或素材。

- **相同的部分：**
  - 图先行的作品流；
  - 导航分"浏览"和"资源"；
  - 技能是资源中的一项；
  - 有赞助页。
- **我们保留的区别：**
  - 每条附出处、核对日期和我们写的笔记（研究什么、用在哪里）；
  - 有 A/B/C 案例；
  - 不转载未经授权的作品图片。
- **定位语：** 和对方几乎一样，这是维护者知情后的选择。副标题用我们的区别（每条都附出处和笔记）来补足。

## 3. P2：交互和审美（本地验证通过，待截图审阅）

"上升一大截"按 `adjective-translation.md` 拆成可以检查的项，每项都要有改动前后的证据。

### 浏览

- 网站和 X 动效合成一条作品流，默认按收录时间排序。分类仍可筛选，并写进地址。
- 卡片只露图片。名称、出处和作者头像在悬停或聚焦时出现；触屏上常驻一行。
- 视频在可见时静音循环。减少动效时只显示封面。

### 打开

- 从卡片到详情用共享元素过渡（View Transitions）。
- 详情支持 ←/→ 切换和 Esc 关闭，关闭后回到原来的滚动位置。

### 视觉

- 作品流去掉卡片边框和底色块，靠间距分组。
- 1440 宽度下首屏至少露出两行作品。
- 计数预算：字号 ≤ 7、文字颜色 ≤ 5、圆角 ≤ 3，用 `scripts/style-budget.mjs` 在 1440 和 390 两个宽度都要量。

### 验收

- Playwright 覆盖：键盘切换、过渡在减少动效时关闭、滚动位置恢复。
- 截图对比：320 / 390 / 1440，中英文。
- 计数报告。

## 4. P3：投稿和授权（本地验证，待审阅）

图先行需要更多真实图片。来源只有两种：

- 作者授权：投稿表单收图片或视频、作者署名、授权范围和撤下方式，进入人工审核；
- 官方嵌入。

授权作品在卡片上标"作者授权"，和"仅链接"区分。现有 `/submit` 的规则沿用，需要补的是收图片的流程和存放方式。存放方式要单独评估：仓库体积、Vercel Blob，或者作者自己托管的地址。

## 5. 不做的

- 不截取未经授权的网站截图，也不下载 recent.design 的素材。
- 不复制 recent.design 的页面结构细节，包括卡片样式和文案。
- 不改技能本身的行为。


## 6. P2 实施记录（2026-11-04）

- 文档编号从 006 调整为 008，避免与已合并的产品架构 RFC-006 冲突。
- 历史 `addedAt` 来自条目首次出现的 Git 提交时间，不把观察日期或 X 发帖日期冒充收录时间。
- 分类、专题、搜索、排序和已有追踪参数保存在 URL；默认按收录时间，另保留编辑顺序、核对时间和名称排序。
- 浏览器回归使用自行生成的 64×40、2 秒纯色视频，不下载 X 视频，验证实际播放/暂停和偏好切换；图片与第三方嵌入在回归中隔离，真实来源画面通过 Ego 浏览器另行查看。
- 原理核对：[Chrome View Transitions 指南](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/same-document-transitions) 的名称唯一要求；[Chrome dialog 滚动指南](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/prevent-page-scroll-under-modal-dialog) 的 dialog/backdrop 滚动隔离。实际本地浏览器结果见执行记录，文档本身不作为跨浏览器支持证明。
- 本地证据和剩余 gate 见 `docs/research/2026-11-04-backlog-execution.md` 与 `2026-11-04-inspiration-budget.json`。尚未部署或宣称生产验收。


## 7. P3 实施记录（2026-11-04）

- 存放方案比较见 `docs/research/2026-11-04-submission-intake.md`。选择作者提供的 HTTPS 地址；作者也可在 GitHub 投稿编辑器上传本地图片/视频，把生成地址填回表单。本站不新增云上传、Blob 账户或媒体仓库。
- `/submit` 双语表单准备可读投稿正文与可下载草稿；未发送状态明确。作者自己在 GitHub 粘贴、检查并提交，自动化不代发。
- `website/src/authorized-references.json` 是经人工核对后登记的来源；当前为空，没有编造许可。`review` 只准备候选，`admit` 要求授权证据、审核者/日期、署名、媒体和翻译状态，写前备份并拒绝冲突/符号链接。
- 卡片、详情和参考包区分作者授权与仅链接，授权只包含本站作品流及详情展示。未审英文标 draft，生产不发布对应语言的页面和索引。
- `withdraw` 将当前登记替换为只含稳定 ID、名称、日期、原因的撤下记录。客户端和预渲染同源；详情 noindex、无媒体，不进作品流和 sitemap。旧的私人笔记保留在本地并标为不可用，不再进入参考指令。旧提交、缓存和已下载文件无法远程收回。
- 维护者操作见 `website/SUBMISSIONS.md`；测试、截图及剩余审核门槛见执行记录。没有真实投稿者测试或生产上线的声明。
