## 问题与目标

现有隔离 React 助手刻意不读取任意项目 Vite 配置。测试简单 TSX 成功，不能证明真实 alias、provider、全局样式、资源与接入仍有原本语义。已补注册系统扩展的证据与接入基准保护，但它们不能证明预览适配正确。

先增加一个自写的 Vite/React 工作室账单界面 fixture，再让真实 Agent 按现有原生隔离适配流程完成生成与可回滚交付。宿主独立打开产物并执行固定业务行为；不根据 Agent 声称“已验证”的文本评分，不用正则代替产品判断。

## Fixture 契约

全部业务和素材由我们自写；账单、工作室和付款状态都是内存示例，没有真实支付、客户资料或网络服务。

1. 原项目的 alias 指向 `src/`；业务 hook/provider 自身也使用 alias，不能只让一个无依赖标题成功渲染。
2. 原 provider 管理工作室、角色与内存账单状态；缺少 provider 时 hook 明确报错。两个工作室的数据与权限不同，切换后视图必须改变。
3. 原业务 hook 提供搜索、状态过滤和标记已付；只读角色不能执行付款状态修改。保留明确控件标签供键盘用户与自动检查使用。
4. 全局品牌 CSS、局部资源 SVG 和原 Vite/TS 配置不可改写。每个方向使用相同任务和数据，可以改变布局、阅读顺序和取舍。
5. 预先放置一个同名预览入口，验证 Agent 选择新路径，不覆盖旧文件。

## Agent 流程与产物

使用只在点名时运行的两轮 fixture，避免增加默认矩阵成本：

- `generate`：创建 A/B/C、原生隔离入口和可运行的构建/类型检查配置，保留原 provider、alias 与全局样式，不选定。
- `deliver`：按明确请求修改 B 的一个局部，再通过真实 helper 撤回；把 B 接入原入口、执行原检查，再回滚。保留各计划、快照、备份和交付说明，最终选择保持空。

原生预览清单放在项目 `.variant-work/`，标明比较页、各版 HTML 入口、适配文件、构建/类型检查配置和依赖来源。所有路径必须在项目内且无符号链接；命令文本用于说明，宿主不把任意 shell 字符串当成待执行指令。每个预览根标明其 A/B/C 身份，比较页链接三个独立入口。

宿主使用项目自己的已安装 Vite 启动原配置，单独执行类型检查与原生预览构建。生成的构建配置复用原项目配置、只覆盖隔离预览的入口和输出位置，不替换生产入口或依赖版本。缺少清单、配置、工具或行为观察时记为失败/未验证，不能从 HTTP 200 推断成功。

## 独立观察与证据

每轮完成后保存源码/上下文快照，在 1440 与 390 宽度打开比较页和三版，记录真实 URL、工具版本、控制台错误、截图、资源加载与业务结果。观察内容：

- 三版身份与键盘可达控件；搜索、过滤、空结果与恢复。
- 工作室切换后的真实数据/角色；允许角色修改内存状态、只读角色受到限制。
- 实际全局品牌样式与本地资源；页面无横向溢出。
- 在独立副本中改变原 provider 的标签和全局 CSS 标记，重新打开预览。结果必须跟随原依赖变化，以发现克隆 provider、硬编码旧数据或忽略全局样式。原 Agent 项目保持不变。
- 修改/撤回的快照、B 的版本和 A/C 字节；真实 helper 调用与最终未选定状态。
- 对已回滚项目的副本重放接入：备份/目标哈希与记录一致，实际原入口呈现 B 并保留业务；再回滚恢复原入口。此宿主重放与 Agent 的动作分别记录。

先运行原 fixture 的检查和页面，保留已观察的原有失败。模型失败、适配失败、项目原有失败和宿主工具失败分开记录；相同失败不改写成通过。生成产物变动后不沿用旧观察。

## 验收门槛

- 有实际 provider/alias/global-CSS 正例及缺 provider、错误入口或复制依赖等负例；测试调用真实 Vite 与浏览器。
- 至少一次真实 Codex 安装/生成/交付运行和独立宿主观察；Claude 账号未恢复时明确保留该缺口。
- 保留原源码、既有预览入口和依赖锁；新文件在获准目录内。接入和回滚不选择方案，不覆盖用户后续修改。
- 原项目与预览的类型检查和构建实际执行；报告与产物身份、配置及工具版本对应。
- 记录读取量、用量和局限；人工视觉验收独立于机械通过。

## 后续边界

本轮验证一个 Vite 项目适配，不把它推广为任意配置、路由或 provider 自动支持。安全清理生成预览文件的归属机制、通用共享依赖发现和完整交付凭证仍需后续实现；Next 等框架另设门槛。#18 自动任务验证计划也保持开放。没有生产部署、付费开通或第三方消息。
