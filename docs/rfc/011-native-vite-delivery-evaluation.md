# RFC-011：原生 Vite 预览与交付实测矩阵

状态：执行设计草案，未验收。范围来自 #19 / PRD-003 的既有首期要求；本文不新增框架支持承诺，也不替代真实运行记录。

执行进展：已接入宿主原生预览、真实类型检查/构建覆盖、独立副本依赖探针，以及接入/历史/回滚重放。真实 Codex 两轮产物经版本绑定的纠正宿主复测通过 45/45；两份原始失败报告保留，维护者视觉验收与完整 #19 仍开放。准备与预览记录见 `docs/research/2026-11-04-native-vite-matrix.md`，重放及复测方法见 `docs/research/2026-11-04-native-vite-delivery-replay.md`。

## 问题与目标

现有隔离 React 助手刻意不读取任意项目 Vite 配置。测试简单 TSX 成功，不能证明真实 alias、provider、全局样式、资源与接入仍有原本语义。已补注册系统扩展的证据与接入基准保护，但它们不能证明预览适配正确。

先增加一个自写的 Vite/React 工作室账单界面 fixture，再让真实 Agent 按现有原生隔离适配流程完成生成与可回滚交付。宿主独立打开产物并执行固定业务行为；不根据 Agent 声称“已验证”的文本评分，不用正则代替产品判断。

## 现状与版本依据

- `react-preview.mjs` / `static-preview.mjs`：覆盖可移植组件；需要原生功能时由 Agent 建立隔离入口，见 `references/workflow/preview.md`。
- `evals/run.mjs`：安装当前工作树、记录真实 CLI 与每轮快照；现已接入原生 Vite 宿主运行观察、依赖探针与独立交付重放。
- `project-profile.mjs`：有界词法依赖发现；alias 和语义关系仍需要 Agent 审查，不能宣称完整依赖图。
- 复用现有 harbor fixture 的精确依赖版本：React 19.1.1、Vite 7.1.7、Rollup 4.65.1。运行时 helper 不增加依赖。
- 2026-11-04 阅读了 Vite 官方 v7.1.7 的 [alias/root 配置](https://github.com/vitejs/vite/blob/v7.1.7/docs/config/shared-options.md)、[构建与多入口](https://github.com/vitejs/vite/blob/v7.1.7/docs/guide/build.md)、[JS API](https://github.com/vitejs/vite/blob/v7.1.7/docs/guide/api-javascript.md)。当前官网已描述 Rolldown；本 fixture 按锁定的 Vite 7 使用 Rollup 配置。dev 与 build 分进程运行，避免共享 NODE_ENV 的干扰。

## Fixture 契约

全部业务和素材由我们自写；账单、工作室和付款状态都是内存示例，没有真实支付、客户资料或网络服务。

1. 原项目的 alias 指向 `src/`；业务 hook/provider 自身也使用 alias，不能只让一个无依赖标题成功渲染。
2. 原 provider 管理工作室、角色与内存账单状态；缺少 provider 时 hook 明确报错。两个工作室的数据与权限不同，切换后视图必须改变。
3. 原业务 hook 提供搜索、状态过滤和标记已付；只读角色不能执行付款状态修改。保留明确控件标签供键盘用户与自动检查使用。
4. 全局品牌 CSS、局部资源 SVG 和原 Vite/TS 配置不可改写。每个方向使用相同任务和数据，可以改变布局、阅读顺序和取舍。
5. 预先放置一个同名预览入口，验证 Agent 选择新路径，不覆盖旧文件。

## Agent 流程与产物

使用只在点名时运行的两轮 fixture，避免增加默认矩阵成本：

- `generate`：创建 A/B/C、原生隔离入口和可运行的构建/类型检查配置，保留原 provider、alias 与全局样式，不选定。
- `deliver`：按明确请求修改 B 的一个局部，再通过真实 helper 撤回；把 B 接入原入口、执行原检查，再回滚。保留各计划、快照、备份和交付说明，最终选择保持空。

原生预览清单放在项目 `.variant-work/`，标明比较页、各版 HTML 入口、适配文件、构建/类型检查配置和依赖来源。所有路径必须在项目内且无符号链接；命令文本用于说明，宿主不把任意 shell 字符串当成待执行指令。每个预览根标明其 A/B/C 身份，比较页链接三个独立入口。

宿主使用项目自己的已安装 Vite 启动原配置，单独执行类型检查与原生预览构建。生成的构建配置复用原项目配置、只覆盖隔离预览的入口和输出位置，不替换生产入口或依赖版本。缺少清单、配置、工具或行为观察时记为失败/未验证，不能从 HTTP 200 推断成功。

## 独立观察与证据

### 直接保存每轮归档

原生 fixture 在 baseline、每次 CLI 退出后且宿主观察/后续轮次修改前，保存独立目录：`source/`、完整 grader `snapshot.json`、`archive.json` 与落盘的 `receipt.json`。收据本身的哈希进入轮次结果；即使最终汇总前宿主中断，已完成阶段的文件仍保存。归档在 Agent 项目外，已有路径一律拒绝覆盖；未完成的归档保留供诊断，不算通过。源码、上下文、历史、staging、清单和已安装技能文本都保存；明确排除任意层级的 `.git`/`node_modules` 及根 `dist`，排除项写进清单，不把归档称作包含依赖的可执行镜像。

记录每个普通文件的 SHA-256、长度和权限，保留空目录；拒绝源文件或目录符号链接和特殊文件。复制前后核对完整源清单，核对归档副本，并验证 grader 快照的上下文/文件哈希与副本一致；完成后才写收据。收据固定 manifest 和 snapshot 哈希。读取时重新检查哈希、完整路径集合、类型和权限，拒绝新增文件、目录替换或元数据篡改。这里的不可变是 helper 不覆盖、篡改可检测，不声称操作系统级 WORM 或原子文件系统快照。

原生评分新增 baseline/generate/deliver 三个归档门槛：收据有效、阶段一致、每个宿主观察指纹都能对应归档文件。归档失败仍保留诊断和其它检查结果，但整体失败。需要重放时只复制到另一个全新目录，原归档和原项目保持不变；安装依赖/执行命令不属于归档 API。验收覆盖实际复制、后续源修改仍可还原旧版、stale grader 快照、归档篡改/漏文件/额外文件、符号链接、边界与重复写入，以及真实 CLI 两轮产生的直接归档。

每轮完成后保存源码/上下文快照，在 1440 与 390 宽度打开比较页和三版，记录真实 URL、工具版本、控制台错误、截图、资源加载与业务结果。观察内容：

- 三版身份与键盘可达控件；搜索、过滤、空结果与恢复。
- 工作室切换后的真实数据/角色；允许角色修改内存状态、只读角色受到限制。
- 实际全局品牌样式与本地资源；页面无横向溢出。
- 在独立副本中改变原 provider 的标签和全局 CSS 标记，重新打开预览。结果必须跟随原依赖变化，以发现克隆 provider、硬编码旧数据或忽略全局样式。原 Agent 项目保持不变。
- 修改/撤回的快照、B 的版本和 A/C 字节；真实 helper 调用与最终未选定状态。
- 对已回滚项目的副本重放接入：备份/目标哈希与记录一致，实际原入口呈现 B 并保留业务；再回滚恢复原入口。此宿主重放与 Agent 的动作分别记录。

先运行原 fixture 的检查和页面，保留已观察的原有失败。模型失败、适配失败、项目原有失败和宿主工具失败分开记录；相同失败不改写成通过。生成产物变动后不沿用旧观察。

## 验收门槛

### 接入重放的具体契约

宿主先只读检查交付清单与真实历史：B 的 apply/undo 快照须串联，恢复字节须等于生成轮；A/C、品牌和原源码保持基准；接入计划与已回滚的备份、staging 哈希须一致且只涉及 `src/App.tsx`。`beforeChecks`、`afterChecks` 各列 typecheck/build，字段为 `tool`、`command`、`version`、`exitCode`、`log`；日志是各自独立的 `.variant-work/` 文件。`rollback` 为 `{completed:true,log:...}`。宿主不执行这些 command 字符串，也不把这些自述当成浏览器验收。

在完整独立副本内，宿主使用当前真实 helper 重新 prepare，从已记录的临时版本重放 B 修改，实际检查标题以 `— Draft` 结束，然后一次 undo 并核对恢复字节。随后用独立新计划接入保留的 staging，原入口必须实际出现 `data-native-variant="B"`、保留业务任务并通过原检查；最后 rollback，核对全部原文件和三版字节及选择状态。在更小的另一个副本内对修改后的 B/接入目标追加可识别的模拟用户修改，检查 undo、stale apply 和 rollback 实际拒绝且保留修改。这些宿主调用与 Agent 原记录分别标明；不改写原计划绝对路径，不替原 Agent 项目强制恢复。

宿主所有动作及失败均保存结构化检查、helper 内容哈希、真实构建/类型检查输出和浏览器样本。缺日志、假回滚、快照不相符、接入了别的方向、运行失败或漂移保护失效均记失败。手写回归只证明重放器能识别正反例；真实 Agent 两轮及人工视觉检查仍是独立门槛。

- 有实际 provider/alias/global-CSS 正例及缺 provider、错误入口或复制依赖等负例；测试调用真实 Vite 与浏览器。
- 至少一次真实 Codex 安装/生成/交付运行和独立宿主观察；Claude 账号未恢复时明确保留该缺口。
- 保留原源码、既有预览入口和依赖锁；新文件在获准目录内。接入和回滚不选择方案，不覆盖用户后续修改。
- 原项目与预览的类型检查和构建实际执行；报告与产物身份、配置及工具版本对应。
- 记录读取量、用量和局限；人工视觉验收独立于机械通过。

## 后续边界

本轮验证一个 Vite 项目适配，不把它推广为任意配置、路由或 provider 自动支持。安全清理生成预览文件的归属机制、通用共享依赖发现和完整交付凭证仍需后续实现；Next 等框架另设门槛。#18 自动任务验证计划也保持开放。没有生产部署、付费开通或第三方消息。
