# RFC-010 · 比较页区域点选与公开代码检查页

- 状态：具体范围提案，待维护者选择；尚未实现这两项功能。
- 日期：2026-11-04。
- 关联：TODO 第 4 组；RFC-001、003、007；既有 prepare/apply/undo 与静态质量扫描。
- 本文把两个独立决定放在一起审阅；可以只接受其中一项。它们不要求开通托管模型、收费或新存储服务。

## 1. 建议

| 决定 | 建议范围 | 若本版不做 |
|---|---|---|
| 在比较页点选区域 | 做。先支持 HTML/Vite 预览里已声明的可编辑区域；点选后获得准确的“B / hero”修改上下文 | 明确保留自然语言区域指令；不把任意 DOM 框选列为已支持 |
| 公开界面代码检查页 | 做独立 `/checks`。粘贴代码，在浏览器本地运行现有静态规则，展示线索与修法 | 保留 CLI 检查和文档；不增加空目录或没有实际检查的宣传页 |

这两个决定都不包含任意网站在线编辑器、AI 审美评分或自动改用户项目文件。它们分别解决“我指的是页面哪里”和“这段代码有哪些常见交付问题”。

## 2. 当前事实

- `scripts/build-preview.mjs` 已生成 A/B/C iframe、桌面/手机切换和推荐说明，未提供区域选择或消息桥。它只写可重建的比较/预览文件。
- `variant-history.mjs` 的区域修改依赖明确的 zone 标记，并要求先准备候选；点到 DOM 并不能自动证明对应哪个源文件范围。JSX 注释在编译后可能不存在，因此不能把所有画面元素都冒充安全可改区域。
- `quality-gate.mjs` 已导出 `scanSource`，官网生成审计复用它；但模块顶层依赖 Node 的 fs/path，不能直接作为浏览器纯模块使用。普通规则与结构性检查并存，不能只复制一部分正则就声称与 CLI 一致。
- 2026-11-02 的检查页评估是历史记录，规则集后来增加了 review 类生成习惯提示。新页必须读取当前共享核心，不把旧记录的“16 条”当作现状。

## 3. 区域点选的交付合同

用户打开比较页 → 进入“选择区域”模式 → 在 B 的预览点到一个已声明区域 → 看到区域高亮和“B · hero” → 输入修改意图或复制带目标的指令。默认模式仍可操作页面原有按钮；退出点选后恢复正常预览。提供区域列表作为键盘入口，Esc 退出。

- 点选是临时预览状态，既不运行 `select`，也不改变 active/selectedVariant、版本、token 或用户文件。真正修改仍由 Agent 走现有 prepare/apply，一条请求一次 undo。
- 可编辑目标只来自已声明的 zone。新生成的可视区域同步保留可定位的 DOM 标识；旧 HTML 可读取有效注释区域，React 使用明确 DOM 标识。无法确认对应关系时说明“未声明可编辑区域”，不退化为整个页面修改。
- 桥接脚本只进入可重建的预览壳，不修改 A/B/C 原稿或项目生产入口。HTML 相对资源和静态 file 预览仍需保持；原生 Next 等适配器在有真实证据前不列入覆盖范围。
- 父页按 iframe 的 window、允许的来源和消息结构验证；目标只含 A/B/C 与已知 zone ID，不包含源码或可执行命令。HTTP 和不透明来源的 file 预览分别测试，不能把 `origin: null` 当作可信身份。

验收：真实 HTML 与 Vite 两条闭环；视觉点选与键盘列表指向同一标记；普通控件在非点选模式可用；错误窗口/来源/未知 zone 消息被忽略；点选不写上下文；复制目标后由真实 Agent 完成 B 的区域修改和一次撤回，A/C 与区域外字节/代表性行为保持。无区域页面明确不支持。

## 4. `/checks` 的交付合同

一页：代码输入框 → 主动点击检查 → 按 error / warning / review 展示行号、短摘录、规则说明和修法。规则有可引用锚点。页面同时说明哪些仍需运行时检查，不输出 WCAG 合格、审美分数或“可上线”结论。

- 先把 Node-free 的扫描核心与规则元数据提取为单一来源；CLI、生成审计和网页读取同一实现。保留既有规则 ID、严重度、顺序、行号与语义；不复制另一套网页正则。结构性检查也必须迁入。
- 粘贴内容不执行、不上传、不放进地址或默认保存。浏览器 worker 执行扫描，输入变更使旧结果过期；中断/超时明确显示未完成，不能显示空的“通过”。起始输入上限建议 512KiB，超出时要求拆分，不能静默截断。
- 中英文文案集中管理；新英文说明先按 RFC-005 标 draft，生产不公开该英文页，预览可审阅。静态 HTML 提供中文规则解释，交互部分需 JS；不能从 HTTP 200 推断扫描可用。
- 每条说明“为什么提示、怎么修、静态扫描查不到什么”。例如移除 outline 需要看实际焦点替代样式；出现 focus-visible 关键词不证明可访问。用户可复制自己看见的报告；页面不代发消息或自动修复。

验收：相同代码/文件名在 Node、官网生成审计与真实浏览器产生相同 findings；支持实际 HTML/CSS/JSX 案例；输入中的 HTML/脚本只按文本显示；扫描期间输入变更不显示过期结果；空输入/大输入/worker 失败有明确状态；网络回归确认代码未被发送；中英文生产可见性、键盘操作与移动端布局有浏览器证据。公开发布仍遵守生产批准流程。

## 5. 实施顺序

收到范围选择后，先做区域点选的只读桥与完整回归，再做共享扫描核心的等价提取，最后做 `/checks`。两个任务各用分支、PR 和证据记录。若只接受其中一项，另一项明确记录为本版不做；不伪装成已实现。

## 6. 标准核对与限制

2026-11-04 直接读取 WHATWG 的 [Cross-document messaging](https://html.spec.whatwg.org/multipage/web-messaging.html) 和 [Origins](https://html.spec.whatwg.org/multipage/browsers.html#concept-origin-opaque)：来源与数据结构都需要验证，不透明来源序列化为 null。由此推导出的本项目设计是“来源检查 + 精确 frame 身份 + 已知目标白名单”，而不是只检查一个字符串。尚未运行区域桥浏览器实验，因此这仍是待验证设计。

本提案未运行或基准测试任何第三方设计服务。它不改变第三方素材权限、付费范围或当前模型开放状态。
