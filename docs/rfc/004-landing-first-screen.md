# RFC-004 · 首页：让第一屏证明"一个任务，三个方向"

- 状态：提案，待评审。
- 日期：2026-10-29。
- 关联：RFC-001（项目内工作流）、RFC-002（方向库，`/` 为作品流）、RFC-003（设计参考库验证闭环）。
- 参考：Impeccable、Resend、Cursor、Linear、Notion、v0 的公开首页，2026-10-29 用本机 Chrome 以普通访客方式打开，只记录首屏与标题结构。截图不进仓库，不复制其文案、图形或素材（见 `docs/research/2026-10-29-reference-topic-note-check.md`、`2026-10-29-reference-topic-additions.md`）。

## 1. 背景与决策

Variant Design 的价值是让访客看到同一个任务被做成三个可以比较的方向，然后在自己的项目里生成、比较、撤回、接入。现在的首页主要靠文字讲这件事，能证明它的真实 A/B/C 记录要往下滚才看到。网站还有两个各说各话的落地页。

提议：

1. **第一屏放证据。**把已有的真实 A/B/C 记录（`HomeCase`，Pulse）提升为首屏主视觉，访客不滚动就能切换 A、B、C，并看到每个方向的重点与取舍。
2. **主张之后紧跟开始方式。**一行可复制的安装方式和第一句指令，直接链接 `/docs`。
3. **只保留一个落地页。**`/` 继续承担 RFC-002 的作品流，把 `/about` 中仍然成立的内容并入首页，`/about` 改为理念文章或重定向，具体在 §9 决定。
4. **首页设计本身用技能产出。**以"重做首页首屏"为任务，在 `website/` 里跑一次 Variant Design，比较 A/B/C 后再选。这次运行就是一次真实的自用测试，也是首页可以引用的证据。

不做：营销式的数字墙、未经核实的客户 logo、星标、证言、"支持所有 agent"之类的说法；不为首页另做一套生成器（RFC-002 已把网站上的生成收进实验室）。

## 2. 现状（2026-10-29，master `470d207` 本地构建，1440 × 900）

| 观察 | 证据 | 问题 |
|---|---|---|
| `/` 首屏只有标题"一个任务，三个方向。"、一句说明和两个按钮 | 截图；`LibraryPage.tsx` `Feed` | 主张没有被画面证明 |
| 真实 A/B/C 切换（`HomeCase`）从页面 y≈1028 px 开始 | 浏览器测得 `.home-case` 位置 | 在 900 px 高的视口里看不到 |
| 主按钮"寻找设计参考 ↗"文字计算色为 `#232622`，背景 `#2E4325` | `getComputedStyle`；`.library-action-primary` 声明了 `color:#fff`，但没有生效 | 对比度约 1.4:1，远低于 WCAG AA 的 4.5:1。与改版无关，应先修 |
| `/about` 首屏是另一句主张"好设计，从看见可能开始。"，Forma 预览也在折叠线以下 | 截图；`PaperLanding` | 两个入口两套说法；Forma 是概念作品，不是技能产出 |
| 首页按钮先引向 `/inspiration`，安装方式只在导航"开始使用"里 | 截图 | 想试用的人要多找一步 |
| 网站没有分析工具 | 代码中没有 analytics 依赖或脚本 | 改版效果只能靠任务观察和 Search Console，不能声称转化提升 |

可用的真实证据（`website/content/entries/`）：

| 条目 | 来源 | 类别 | 可以怎样用 |
|---|---|---|---|
| Pulse | 技能产出 · 已验证 | 数据展示 | 首屏 A/B/C 的默认案例（已在 `HomeCase` 使用） |
| Harbor | 技能产出 · 已验证 | 产品界面 | 第二个可切换案例 |
| Variant Design 官网 | 技能产出 · 已验证 | 落地页 | 首页自身的产出记录；本 RFC 的自用测试会产生新一轮 |
| Forma、offscript | 概念作品 | 数据、品牌 | 只能放在作品流里并标注"概念作品"，不能当作技能产出证据 |

已实测的 agent：eval 基线（`docs/research/2026-10-27-eval-baseline.md`）跑过 Claude Code 2.1.311 与 Codex CLI 0.163.0。首页只能列这两个，并写出依据。

## 3. 参考：借什么、不借什么

| 参考 | 首屏做法（观察） | 借鉴 | 不借鉴 |
|---|---|---|---|
| Impeccable | 可拖动的前后对照，标注具体问题（如"AI kicker""Italic serif"），下方切换 /polish、/distill、/clarify | 一次可操作的对比证明价值；标注写具体取舍，不写形容词；切换控件就是产品的真实命令 | 一排 agent logo、星标数；对照中的"前"是刻意做差的样例，我们只展示真实记录 |
| Resend | 只面向开发者的主张，两个按钮，随后就是 Integrate 代码段 | 主张之后紧跟开始方式；受众写清楚 | 极简留白导致首屏没有产品画面 |
| Cursor | 主张后直接展示 agent 完成一个具体任务（Build Landing Page） | 用真实会话片段说明"在你的项目里发生"：任务 → A/B/C → pick → 撤回 | 合成的演示会话；我们只截取已记录的运行 |
| Linear、Notion | 一句主张，首屏即可看到产品界面，之后按工作流分段 | 后续分段按工作流排：生成 → 比较 → 局部修改与撤回 → 接入 | 客户 logo 墙 |
| v0 | 首屏是输入框和示例起点 | 不采用：网站不生成，生成发生在用户项目里（RFC-002） | — |

## 4. 受众与首页要完成的任务

主要受众：在自己项目里用 Claude Code 或 Codex 做界面的人（独立开发者、小团队设计工程师）。次要受众：从作品流或参考库进入、还没安装的人。

| 时间 | 访客应能做到 |
|---|---|
| 首屏，约 10 秒 | 说出产品做什么（一个任务出三个方向）；亲手切换一次 A/B/C；看到怎样开始 |
| 约 1 分钟 | 理解它在自己的项目里运行、可以撤回、由自己选择；复制安装方式或第一句指令 |
| 之后 | 浏览更多案例或参考，或去 `/docs` 走完一次 |

## 5. 页面结构

```
首屏（1440×900 与 390×844 都不滚动可见：主张、A/B/C 切换、开始方式）
┌──────────────────────────────┬──────────────────────────────────────┐
│ 主张（一行）                  │ [A] [B] [C]  真实预览（Pulse）         │
│ 一句说明：在你的项目里生成、   │ 重点：…   取舍：…                      │
│ 比较、撤回，由你选择           │ 技能产出记录 · 查看完整案例 ↗          │
│ [复制安装方式] [看完整案例 →] │                                        │
│ 已实测：Claude Code · Codex   │                                        │
└──────────────────────────────┴──────────────────────────────────────┘
1 工作方式：生成 → 比较 → 局部修改与撤回 → 接入，每步一条真实命令或会话片段
2 案例作品流（RFC-002 现有 Feed 与分类，"技能产出 / 概念作品"标注保持不变）
3 从参考开始：链接 `/inspiration`，说明参考包与 brief（RFC-003）
4 页脚：安装、投稿与授权、实验室
```

规格：

- **主张。**一句话，中英各一。候选沿用"一个任务，三个方向。"；是否改写由 §8 的 A/B/C 产出决定，不在本 RFC 定稿。
- **A/B/C 切换。**沿用 `HomeCase` 的数据和组件，不新造演示：
  - 默认显示条目推荐的方向（Pulse 为 A）。
  - 可选第二个案例（Harbor），切换时保留"技能产出记录"标注。
  - 控件是带 `aria-pressed` 的按钮组，支持键盘；说明区用 `aria-live="polite"`。
  - 图片给出宽高，首屏图片按 LCP 处理：不懒加载，提供合适尺寸。
  - 窄屏改为上下排列，切换控件在图片上方。
- **开始方式。**
  - 显示一条可复制的安装命令，与 `/docs` 使用同一数据源（`DocsGuide.tsx` 的 `agents`）。复制失败时提示手动复制，沿用参考页的处理。
  - 第二个按钮去 `/d/pulse` 或 `#works`。
  - "寻找设计参考"降为第 3 段的入口。
- **已实测标注。**写"已在 Claude Code、Codex 中实测"，并链接 eval 记录或 `/docs`。版本号以最新 eval 记录为准；没有新记录时不更新。
- **工作方式段。**每步配真实素材：命令来自 `references/workflow/history.md` 的用户说法（如 `pick B`、`undo`），会话片段来自已保存的运行记录，标注日期与 agent。没有记录的步骤只写文字，不配假截图。
- **双语与预渲染。**
  - 首屏文字纳入 `scripts/prerender.mjs` 的 `/` 输出。
  - 标题、描述与可见主张一致。
  - 语言切换沿用现有方式，多语言 URL 属于 RFC-003 §5，本 RFC 不改。

## 6. 内容与证据契约

- 首屏和工作方式段只使用技能真实产出的记录（`source: own`、`kind: verified`）。概念作品只在作品流里出现，并保留标注。
- 每个展示的产出都要能追到记录：条目 JSON、`evidence/`、或 `docs/research/` 中带日期的文件。
- 不显示没有来源的数字（用户数、星标、生成次数、节省时间）。不显示第三方 logo 或证言，除非取得授权并在 `docs/research/` 记录依据。
- 支持的客户端只写实测过的，并注明依据。
- 首屏不托管第三方参考的截图；参考仍按 RFC-003 只给链接。

## 7. 视觉方向的约束

视觉的具体方向由 §8 的 A/B/C 产出决定。无论选哪一版，都要满足：

- 沿用 `src/design-system.css` 与 `site-system.css` 的 token，不在首页另起一套颜色和字体。如需调整 token，单独提交并说明影响到哪些页面。
- 文字与背景对比度至少 4.5:1（大字至少 3:1），用计算样式检查，不靠目测。
- 尊重 `prefers-reduced-motion`；切换动画不超过 200 ms，关闭动画后功能不变。
- 320、390、1440 宽度下没有横向滚动。

## 8. 用技能产出首页（自用测试）

1. 在独立分支和 worktree 中，以本 RFC §4–§7 作为任务和约束，用当前 master 的技能在 `website/` 里生成首屏的 A/B/C。按 AGENTS.md 的规则，确认运行读到的是这棵工作树里的技能，不是全局安装；用 `--output-format stream-json --verbose` 检查读取路径，或在 eval 式隔离环境中运行。
2. 记录宿主与版本、指令原文、读取的技能文件、耗时与用量、三版的重点与取舍、推荐理由。在 `docs/research/YYYY-MM-DD-landing-first-screen-dogfood.md` 写明哪些步骤顺利、哪些需要人工干预。
3. 由维护者比较后用 `pick` 选定，再走 `variant-integrate.mjs` 接入和回滚路径。技能不替用户选择。
4. 选定后，把这一轮作为新的"Variant Design 官网"产出记录，按 RFC-002 的条目结构加入或更新 `website/content/entries/variant-site.json`，附截图与证据。

如果技能在这个任务上表现不好，照实记录问题，回到技能本身改进，不为了首页手工修饰成果再声称是技能产出。

## 9. 分阶段

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| P0 | 修复主按钮对比度（§2），加计算样式回归测试 | 测试断言主按钮对比度 ≥ 4.5:1；1440 与 390 截图人工查看 |
| P1 | §8 自用测试，产出三版首屏与记录 | `docs/research/` 有记录；维护者完成选择 |
| P2 | 实现选定方向：首屏 A/B/C、开始方式、工作方式段；`/about` 合并或改为文章 | §10 验收全部通过；旧链接仍可访问 |
| P3 | 观察：与 RFC-003 的任务观察合并进行，记录首页部分的结果 | `docs/research/` 有带日期、样本与局限的记录 |

P0 与本 RFC 是否通过无关，可以立即进行。P2 之前需要确定 §11 的待决定项。

## 10. 验收

自动（`tests/landing.spec.mjs`，使用真实构建）：

- 1440 × 900 与 390 × 844 下，不滚动即可在视口内看到 h1、A/B/C 切换和开始方式按钮。
- 切换 A/B/C 后，图片、重点和取舍更新，按钮的 `aria-pressed` 正确，键盘可以操作。
- 首屏展示的条目全部是 `kind: verified`，并显示"技能产出记录"标注。
- 主要按钮与正文的计算对比度 ≥ 4.5:1。
- 复制安装方式成功与失败都有反馈；命令与 `/docs` 一致（共用数据源）。
- 320、390、1440 宽度没有横向滚动；开启 `prefers-reduced-motion` 后切换仍可用。
- 预渲染的 `/` 包含主张文字，title 与 description 与页面一致；`/about` 的旧链接仍可访问（200 或 301 到对应位置）。

人工与记录：

- §8 自用测试记录完整。
- 中英文分别查看一次首屏。
- 没有分析数据时，不声称跳出率、转化或安装量的变化。任务观察只说明观察到了什么，并注明样本数。

## 11. 待决定

1. `/about` 改为理念文章，还是 301 到 `/`？前者保留现有外链的语义，后者减少维护。
2. 首屏默认案例用 Pulse（数据展示）还是"Variant Design 官网"（落地页，与访客当前看的页面同类）？
3. 首屏是否同时提供 Harbor 作为第二个案例，还是只放一个，以减少选择？
4. 主张是否改写，由 §8 的三版比较决定。
5. 是否引入隐私友好的分析工具。引入前需要单独决定数据范围、保留期与告知方式（RFC-003 §4 的私有内容不入分析的约束同样适用）。

## 12. 风险

| 风险 | 应对 |
|---|---|
| 首屏变成堆满元素的拼贴，反而更难懂 | 首屏只放三样：主张、A/B/C、开始方式。其余内容下移 |
| 为了好看挑选或修饰产出，与"真实记录"矛盾 | §6 契约；首屏素材必须能追到记录，修饰过的版本不能标为技能产出 |
| 首屏图片变大，拖慢加载 | 控制图片尺寸与格式，验收中检查首屏图片的加载方式；需要时补充 LCP 测量 |
| 自用测试结果不理想 | 照实记录，先改技能；首页可以暂时只做 P0 并把 `HomeCase` 上移 |
