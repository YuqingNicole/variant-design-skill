# 外部试用手册（PRD-007）

目的：让没有参与开发的人，在**自己的真实项目**里走完一次完整流程，并记录他们在哪里完成、在哪里卡住、在哪里需要帮助。对应 PRD-007 的验收项 F1–F7。试用结果写成 `docs/research/` 下的记录，不当作转化率或满意度结论。

## 1. 找谁

- 目标 3–5 人，至少 2 人完成全程（PRD-007 F7）。
- 每人带一个自己正在维护的前端项目，项目里有一个他们本来就想改的页面。
- 尽量覆盖不同情况：
  - 至少 1 个 Next.js 项目；
  - 至少 1 个有品牌规范或设计系统的项目；
  - 至少 1 个纯 HTML、或没有构建步骤的项目。
- 已经在用 Claude Code 或 Codex 的人。这次不测"装 agent"这一步。
- 不找参与过本项目开发或评审的人。

## 2. 事先告诉对方

可以直接转发：

> 我们在测试一个开源的设计技能 Variant Design。它在你自己的项目里，针对一个页面生成三个不同方向的设计，你比较后可以改、撤回，最后选一个接回项目。
>
> - 全程在你电脑上运行，用你自己的 agent 和模型额度（Claude 每生成一次大约 $2–3）。我们不会拿到你的代码。
> - 它只在项目里新建 `variant-output/` 和 `.variant-work/` 两个目录；接入原项目前会先备份，可以一键撤回。建议先提交一次 Git，或者在新分支上试。
> - 大约 60–90 分钟。我们会在旁边看（线上共享屏幕也可以），记录你在哪里卡住。卡住时尽量先自己试，实在不行再问。
> - 记录只写步骤、耗时和问题，不写项目名称和代码内容；如果你同意，可以附上截图。

## 3. 开始前检查（观察者做）

- [ ] Node.js 22 或以上：`node -v`
- [ ] 项目已提交一次 Git，或者在新分支上
- [ ] 记下 agent 的名称和版本：`claude --version` / `codex --version`
- [ ] 记下技能版本：安装后执行 `cat <安装路径>/VERSION`
- [ ] 打开计时

## 4. 任务（按顺序，给对方看的是"说法"一列）

不要提示具体命令。对方问到时，记成"求助"，再给最小提示。

| # | 说法 | 对应验收 | 观察什么 |
|---|---|---|---|
| T1 | "按网站上的说明装好这个技能：https://variant-design-skill.vercel.app/docs" | 安装 | 用了哪种安装方式；能否确认装好了 |
| T2 | "让它看看你的项目，先别生成。" | F1、RFC-001 | agent 复述的页面范围、核心任务、品牌约束是否正确 |
| T3 | "让它给你想改的那个页面出三个方向。" | F1、F2 | 耗时；三版能否打开；三版是否用同样的数据和功能；说明和推荐看不看得懂 |
| T4 | "挑一个方向，只改其中一块，比如顶部。" | F3 | 对方怎么表达"只改一块"；其他部分和另外两版有没有被动到 |
| T5 | "撤回刚才的修改。" | F3 | 能否撤回；撤回后是否回到原样 |
| T6 | "关掉这个会话，新开一个，接着刚才的进度。" | F5 | 新会话能否读到之前的状态；有没有重复生成或覆盖 |
| T7 | "选定一个方向，接回你的项目。" | F6 | 接入前是否列出要改的文件；接入后项目能否运行；是否给了撤回命令 |
| T8 | （可选）"把它撤回，项目恢复原样。" | F6 | 回滚是否成功；对方之后手动改过的文件有没有被保护 |

如果中途出现不支持的框架、依赖缺失或模型失败，记下 agent 停在哪一步、是否说清楚原因、能否继续（F4）。

## 6. 结束后问 4 个问题

1. 如果没有我们在旁边，你会在哪一步放弃？
2. 三个方向里，有没有你自己想不到、但值得考虑的？
3. 这次花的时间和费用，换来的结果值不值？如果不值，要怎样才值？
4. 下次改页面，你还会用吗？在什么情况下会用？

## 7. 之后怎么处理

- 每份记录整理成 `docs/research/YYYY-MM-DD-trial-Pn.md`：不写项目名称，不贴代码。
- 每个卡点开一个 Issue，标签 `trial`，写明复现方式。
- 能写成确定检查的问题，加进自动实测（`evals/`）：新增示例项目或检查项。
- 至少 2 份完成全程的记录之后，再更新 PRD-007 的验收清单。
