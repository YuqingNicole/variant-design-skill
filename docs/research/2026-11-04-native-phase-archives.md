## Format and boundaries

`evals/phase-archive.mjs` creates a new outside-project directory containing `source/`, `snapshot.json`, a completion `archive.json` and durable `receipt.json`. The native runner captures baseline before its browser checks and each completed CLI turn before observation or the next turn. The receipt's own hash is stored with the run and each turn. Phase evidence is already on disk if the host stops before the final summary. The grader adds three archive gates, bringing a complete two-turn native case from 45 to 48 checks. Earlier results retain their original meaning; missing archives are not silently backfilled.

Capture preserves ordinary source, context, hidden history, staging, manifests, installed skill text, empty directories and file/directory permission bits. `.git`/`node_modules` at any depth and root `dist` are explicit exclusions, with observed paths recorded. Dependencies are not a source archive; no install/build command is run by this API. Source/archive symlinks and special files are rejected. New output paths are canonicalized and must be outside their source roots. Existing and partial archives are never overwritten or repaired in place.

The completion receipt anchors the manifest, snapshot and source digests. Creation compares source before/after copying, validates the copied tree and full grader snapshot, and only then writes completion metadata. Verification reads every archived entry without applying exclusions again, rejecting added ignored-looking files as well as missing bytes, metadata/mode changes and links. Materialization copies verified bytes into another fresh outside-project directory, preserving old state without modifying either original source or archive. This is write-once-by-helper plus tamper detection, not WORM storage or an atomic filesystem snapshot. Invalid context is retained as failed-phase diagnostic data without migration.
