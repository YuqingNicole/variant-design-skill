# `www` 子域名的 HTTPS 修复（2026-11-14）

对应 TODO 第 2 组的 Search Console 一项。起因：维护者转述 Google 的反馈，“网页必须采用 HTTPS 协议，才符合‘良好’网页体验资格”。

## 修之前查到的

对线上站点发了几个只读请求（`curl -I`、`dig`、`openssl s_client`），并用 Vercel CLI 只读查看了域名（`vercel domains inspect`）。

| 地址 | 结果 |
|---|---|
| `https://variantdesign.xyz/` | 200，带 `strict-transport-security: max-age=63072000` |
| `http://variantdesign.xyz/` | 308 到 `https://variantdesign.xyz/` |
| `http://www.variantdesign.xyz/` | 308 到 `https://www.variantdesign.xyz/` |
| `https://www.variantdesign.xyz/` | 证书错误：证书只有 `DNS:variantdesign.xyz`，不含 `www` |

- 原因：DNS 里 `www` 是指向主域名的 CNAME（解析到 `216.198.79.1`），但 Vercel 项目 `variant-design-skill` 只挂了 `variantdesign.xyz` 一个域名，证书也只签给它。
- 代码没有问题：站点地址在 `website/scripts/prerender.mjs` 里是 `https://variantdesign.xyz`，`canonical` 和 sitemap 由它生成；在 `website/index.html` 和 `website/public/` 里没有搜到 `http://` 的资源引用（只搜了这两处，没有检查构建产物）。

## 做了什么

维护者同意后运行：

```sh
vercel domains add www.variantdesign.xyz variant-design-skill \
  --redirect variantdesign.xyz --redirect-status-code 308 \
  --scope nicolechen-9191s-projects
```

这是 Vercel 项目的域名设置，仓库里没有对应的代码改动。DNS 记录没有动，`vercel domains verify` 直接显示已验证。

## 修之后查到的

约一分钟后复查：

| 地址 | 结果 |
|---|---|
| `https://www.variantdesign.xyz/` | 308 到 `https://variantdesign.xyz/`；证书是 `CN=www.variantdesign.xyz` |
| `https://www.variantdesign.xyz/en/guides?x=1` | 308 到 `https://variantdesign.xyz/en/guides?x=1`，路径和参数保留 |
| `http://www.variantdesign.xyz/en/guides?x=1` | 308 到 `https://www.variantdesign.xyz/en/guides?x=1`，再走上一行的跳转 |

每个地址只请求了一次，没有用浏览器打开。

## 没有确认的

- **Google 的提示是不是因 `www` 而起。** 那句话是 Search Console HTTPS 报告页的说明文字，我的理解是有没有问题都会显示；这一点没有对照 Google 的文档核实。没有看到报告本身，不知道“非 HTTPS 网址”的条数、示例网址，也不知道资源是“网域”还是“网址前缀”。
- **Search Console 资源现在的状态。** `2026-11-07-search-console-readiness.md` 记录的是当时还没有建立资源；这次没有登录 Search Console 核对。
- 修复之后 Google 报告有没有变化。报告更新有延迟。

## 下一步

【维护者】在 Search Console 的 HTTPS 报告里看三项：非 HTTPS 网址的条数、示例网址、资源类型。示例里有 `www` 开头的网址，就点“验证修复”；条数是 0 或显示数据不足，就不用处理。
