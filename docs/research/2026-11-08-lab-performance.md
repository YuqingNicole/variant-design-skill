# 首屏速度的实验室测量（2026-11-08）

对应拆解草稿里的 F1。目的：有一份能重复的速度基线，并在赞助位上线前把"不拖慢首屏"变成会失败的测试。

**这是在一台机器上的实验室数据，不是读者的真实体验。** 没有统计工具（见 `2026-11-08-analytics-state.md`），所以没有真实用户的数据。

## 方法

- 脚本：`tests/perf-lab.mjs`（`cd tests && node perf-lab.mjs [--base URL] [--runs 5] [--out 文件]`）。真实 Chrome，每个配置每页跑若干次，取中位数。
- 指标：LCP、FCP、CLS（Chrome 的 PerformanceObserver）、长任务超出 50ms 的部分之和、最慢的一次交互耗时（Event Timing）、页面加载的脚本和样式的 gzip 体积。2026-11-13 起还记 LCP 对应的元素（标签、id 或第一个类名，加图片地址或开头几个字，`lcpElement`），预算测试在 LCP 超线时把它写进失败信息；之前只有时间，CI 上失败时不知道慢的是什么。
- 每次加载后用页面：打开第一张卡片、按 Esc 关闭、在搜索框输入。**CLS 包含这几步。** "最慢交互"也来自这几步，只有有卡片的页面才有。
- 手机配置：390×844，倍率 2，触屏，CPU 降速 4 倍。**没有限制网络。**
- 本地数据：用本站的 `dist` 在本机服务，第三方图片换成 1 像素占位图，其他第三方请求拦截。所以它反映的是我们自己的 HTML、脚本和样式，不含别的网站的图片。
- 生产参考：同一脚本直接对线上站点跑，真实网络、真实第三方图片，每配置只跑 3 次，来自同一个网络位置。**数据是在下面的修复部署之前取的。**

## 发现

1. **详情页的预览图加载后整页跳动（已修）。** 预览图在详情页写的是 `width:100%; height:auto`，图片没到时高度接近 0，到了才撑开到约 495px，下面的说明文字和页脚被推下去。修复前：桌面 CLS 0.0838、手机 0.1384（超过 0.1 的"良好"线）；修复后 0.0005 和 0。同一个组件也用在卡片弹层里，生产参考里手机上首页和 `/browse/interaction` 的 CLS 是 0.157 和 0.162，我判断是"打开第一张卡片"这一步里弹层中的预览图晚于点击 500ms 才到，同一个根因。**这个判断要等部署后重测确认。**
2. **详情页的 LCP 在本地偏慢（未修）。** 本地 1.2–1.5 秒，其他页 0.1–0.3 秒；生产参考是 0.4–0.5 秒。原因：中文详情页的预渲染正文是一个简化的静态版本（`referenceBody`），完整的详情视图要等脚本加载、React 接管后才出现，最大元素（预览图）也跟着晚。英文详情页是用完整视图预渲染的。可以考虑让中文也一样，这同时会改善没有 JavaScript 时的阅读。改动不小，没有做。
3. **样式体积偏大（未修）。** 每个页面都加载约 81 KB（gzip）的样式，连 `/sponsor` 也是，因为各页面的样式没有按路由拆开。
4. **最慢交互。** 本地手机配置 128–144 ms，生产参考手机配置 200–240 ms。官方"良好"线是 200 ms。这是实验室近似，不是真实 INP，**没有设门槛**。

## 现在由测试保证的

`tests/landing.spec.mjs` 的 "lab budget" 用例（本地、占位图）：

- 四个页面在手机和桌面下 CLS ≤ 0.1（官方"良好"线）。
- `/`、`/browse/interaction`、`/sponsor` 的 LCP ≤ 2500 ms（官方"良好"线）。详情页的最大元素是别的网站的图片，不设 LCP 门槛。
- 首页 gzip 脚本 ≤ 145 KB、样式 ≤ 95 KB，比今天（125.2 KB、81.2 KB）多约 15% 余量。这个余量是我定的，可以改。

去掉预览图的修复后，这个用例会在手机详情页上失败（CLS 0.1384）。

## 没有做

- 没有测真实网络条件（降速网络）；没有真实用户数据。
- 没有测 Safari、Firefox 和真机。
- 发现 2 和 3 没有改。
- 本地数据受第三方图片占位影响：它会让 LCP 和 CLS 看起来比线上好，所以线上的数字要以统计工具为准。

## 2026-11-13 补记：首页数据拆分后的口径

`tests/perf-lab.mjs` 从这天起分开记两项：`kb` 是页面为了渲染而加载的脚本、样式和 HTML 的 gzip 体积；`kbAfter` 是加上操作（打开一张卡、搜索一次）之后的总量。此前只有一项，等于现在的 `kbAfter`。首页脚本自 2026-11-13 起只带每条参考的一行轻数据和第一页的完整记录，其余按分类在读者滚过第一页、排序、搜索或打开参考时才取，所以两项在首页不同：本地构建桌面首页 `kb` 113.8 KB（拆分前 173.0），`kbAfter` 195.8 KB。landing 测试的首页脚本上限按 `kb` 定，130 KB。
