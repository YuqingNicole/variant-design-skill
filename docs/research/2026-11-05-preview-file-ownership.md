# Preview file ownership and cleanup · 2026-11-05

Branch: `codex/preview-file-ownership`, based on PR #158 evidence head `7798f46`. Requirement: #19 / PRD-003 I4 and I9, specified in RFC-012. This record spans the local midnight boundary; earlier preparation is appended in `2026-11-04-backlog-execution.md`.

## Change and boundaries

The comparison builder previously overwrote generated mount/comparison paths, and the static builder recursively removed `_static/`. They now publish complete file maps through a zero-dependency ownership helper. First writes require absent paths; subsequent writes check the complete old receipt before touching targets. Static bundling finishes outside the target before publication. Unknown files are retained, including files inside the generated static directory. Comparison and static publication have separate receipts/transactions; a static conflict does not roll back an already refreshed comparison.

Native adapters prepare an absent path list before writing and seal it once afterward. Later updates stage a complete tree and use guarded publish. A stable `ownershipGroup` in the owned manifest avoids a self-referential receipt path; current receipt paths belong in the handoff. Cleanup is explicit, does not discover/kill processes, and checks each recorded file before unlinking. It leaves all directories, unlisted files, changed bytes/modes, links and replaced files intact. Missing paths are reported separately. Device, inode and creation-nanosecond identities are exact decimal strings; unsupported creation identity is rejected. No force/adoption flag or silent migration exists.

Operation backups are persisted and re-read before writes/deletions. A normal write failure restores only still-matching helper writes, refreshes the ownership receipt after successful restoration, and preserves later edits with conflicts. Missing/changed/stale receipts and a busy lock refuse work. Process interruption and the final check/OS operation race are explicit limits; this is not a global filesystem transaction or cryptographic origin authentication.

The required plugin contents, router/action routing, shared preview/history/export/code rules, generate route and bilingual website/README text are synchronized. Production, integration-helper semantics, final selection and release versions are unchanged. The existing integration helper's plan boundary was retained.
