# Paper（paper.design）公开资料对照

日期：2026-10-26。资料只来自 Paper 的公开页面：首页、`/docs`、`/docs/mcp`、`/compare/figma`、`/compare/pencil`、`/build-log`、`/pricing` 和 `/legal/tos`，均按普通访客的方式逐页阅读。

Paper 的服务条款（第 4 节）禁止对服务做逆向工程、反编译和抓取，也禁止将其用于对标测试或开发竞品。所以本文不分析它的客户端代码、接口或内部实现，也没有使用产品本身做对比测试。下文只记录它公开说明的定位和工作流，并据此判断 Variant Design 应该坚持什么、可以借鉴哪些思路，由我们自己的方式实现。

## Paper 公开说明的定位与工作流

- **定位**：面向"与 agent 一起交付的团队"的联网画布，自称"anti-slop"。画布基于真实的 HTML/CSS，所以设计可以直接变成代码，不需要转换。
- **Agent 接入**：Paper Desktop 内置 MCP 服务器，agent 读写当前打开的文件，包括选中的 frame、tokens、色板和生成的图片。官方给出三种接入：Claude Code、Codex、Cursor，有一键按钮，也有手动命令。接入后用一条测试指令确认，例如"Create a basic Hello World frame in Paper"。
- **以"选中内容"作为上下文**：许多示例指令都依赖"当前选中的 frame"。比如把选中的 hero 生成 React + Tailwind 网站，或者把 Notion 数据同步到选中的 frame。
- **代码与内容双向流动**：tokens 和样式可以在代码库和画布之间同步，画布上改好的文案可以回写到代码；也能用其他 MCP 拉取真实内容，比如 Notion 和 Figma。
- **协作**：多人实时编辑；评论可以同时给队友和 agent；文件里能看到 agent 在场；desktop 标签页让 agent 在多个文件里工作（build log，2026 年 5–9 月）。
- **限制写得很清楚**：Figma 导入的已知缺陷、大文件报错、长会话需要重启、计划额度刷新等问题，在文档里逐条列出。
- **价格**：免费版不限查看者和编辑者，每周 100 次 MCP 调用；Pro 每位编辑者每月 20 美元，每周 100 万次 MCP 调用。

## 与 Variant Design 的差异

| 维度 | Paper | Variant Design |
|---|---|---|
| 主工作面 | 画布（网页端 / 桌面端） | 用户自己的代码仓库和 agent 对话 |
| 产物 | 画布上的设计，可导出或交给 agent 生成代码 | 项目内可运行的 A/B/C 代码与比较页 |
| 方案生成 | 由 agent 和设计师在画布上完成，公开资料没有强调"多方案取舍" | 核心能力：三版共享任务和数据，各自说明优化什么、牺牲什么、适合什么场景 |
| 修改安全 | 公开资料未说明版本回退的语义 | 快照、局部 zone 编辑、`undo B` 不影响其他方案，冲突检测，接入可回滚 |
| 模型 | 用户自己的 agent 加 Paper 的图像模型 | 完全由用户的 agent 提供 |
| 协作 | 多人实时编辑，评论给人和 agent | 目前单人，在 agent 对话里进行 |
| 分发 | 商业 SaaS 加桌面端 | 开源技能，插件候选包 |

结论：两者不在同一个落点。Paper 解决的是"设计在哪里做"，我们解决的是"在真实项目里做出可比较的决定，并安全地交付"。不追画布，继续加深"决定 + 安全交付"这条线。

## 可以借鉴的思路（用我们自己的方式实现）

1. **安装后立即确认可用**。Paper 的做法是：一键接入，用 `/mcp` 确认，再跑一条测试指令。对应到我们：`/docs` 已经加了"确认安装成功"（检查版本，再用一条只读指令确认）。下一步可以做一个 `doctor` 脚本，一次检查 Node 版本、技能路径和 helper 能否运行。
2. **从界面直接指向修改位置**。对应到我们：比较页目前只读。可以在每版的分区上提供"复制指令"，例如点 B 的 hero 就复制 `B vary subtle — hero`，让用户不用记 zone 名称。
3. **把反馈留给 agent**。对应到我们：比较页可以让用户写下对某一版、某个分区的意见，存进 `variant-output/feedback.md`，下一轮由 agent 读取。这符合我们"只读预览、修改在 agent 对话里进行"的边界。
4. **明确列出限制**。对应到我们：`/docs` 的常见问题可以增加"已知限制"：沙箱里预览要用 `--static`、headless 会话里的后台预览服务器、无法验证的项目等。
5. **MCP 适配**。对应到我们：仓库里正在做的本地 MCP 适配器（`mcp/`），可以借鉴"选中即上下文"和"一键加入 Claude / Codex"的接入体验，但工具语义保持我们自己的快照、冲突和回滚规则。

## 不借鉴

画布、多人实时编辑、图像生成模型、按调用次数计费。这些都偏离"在用户项目里交付"的定位，也会带来托管成本和数据边界问题。
