## Replay contract

RFC-011 now defines the delivery receipt's check/log shape and the independent replay. The host inspects generation hashes, original restored source, the complete B apply/undo snapshot chain (including grouped requests), plan/staging/backup identity, actual installed tool versions and distinct log paths. No Agent-supplied command text is executed by the host. Receipt structure/log presence is recorded evidence, not independent proof of its claimed command execution; the host performs actual checks itself.

The complete replay runs in a disposable copy with the project's real installed modules. A fresh prepare/apply replays the recorded temporary bytes, browser checks observe the `— Draft` heading and business tasks, and one real undo restores the generated files/metadata. A new integration plan binds current B, preserved staging is applied, and the original application's entry must render B while retaining original alias/provider/data/global CSS/resource/role/task behavior and passing its original typecheck/build. Real rollback restores all 15 original fixture files and variant/selection state. An original capture now binds registered variant sources too, while the main preview grader still requires all A/B/C samples; the B-only capture is restricted to the explicit history replay.

Separate guard copies append recognizable simulated user edits after history apply, integration prepare and integration apply. The real helpers must reject undo, stale apply and rollback respectively, preserving the later bytes. Original Agent-source hashes before/after, actual helper-call timestamps/hashes, retained plans/backups/logs and browser captures are saved together. The source tree comparison excludes installed modules, Git metadata and build output; it includes source, manifests, histories, staging and installed skill text. No original Agent plan or backup is rewritten to make a new project path fit.
