## Implementation and scope

`project-dependencies.mjs` is read-only. It records local paths/content hashes, reference edges, the resolver/compiler identity, reviewed alias/entry/config facts and explicit coverage limits/unknowns. It follows supported static script imports with the project's existing TypeScript AST API, HTML/CSS resources, local config extends/references and compiler-selected local source/declaration inputs, including local type roots. It does not install a compiler, execute project configuration or import project source. TypeScript 7/incompatible or missing APIs leave script coverage unknown.

Reviewed native wrappers, adapter manifests and separate build/typecheck configs are registered in `.variant-work/dependency-resolution.json` before verification/integration prepare. That file is itself fingerprinted. The existing lexical project profile is still a semantic-review input, not a transaction lock. Runtime alias equivalence, installed package contents, remote/network/data-driven/plugin-generated dependencies and environment require separate review; static candidate sets do not prove runtime resolution. Raw source and full external URLs are not copied into the closure.

Verification before/after/status and integration prepare/apply share this immediate closure. Known source/config/resource/reference/resolver changes invalidate evidence or reject the old plan. Partial coverage keeps actual per-check observations but caps aggregate verification at unverified; old missing-closure evidence/plans are not retrofitted. Integration backups retain the same scope and do not certify runtime acceptance. Target drift is reported before broader source drift so a target present in the closure still receives an actionable target-conflict message. Selection, history-helper semantics, original production configuration and release versions are unchanged.
