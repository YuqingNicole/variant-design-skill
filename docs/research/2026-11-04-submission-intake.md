# 投稿、媒体与撤下 · 实施基线

目标来自 RFC-008 §4：作者提供图片或视频、署名、授权范围和撤下方式，人工审核后展示；卡片区分作者授权与仅链接。

## 存放方式

| 方案 | 影响 | 本次选择 |
|---|---|---|
| 仓库存原媒体 | 历史会持续保留大文件；撤下不能抹掉已有克隆；当前方向库只接受小图 | 保留既有自产案例，不新增投稿媒体到 Git |
| Vercel Blob | 需要存储、上传授权接口、账户配置与用量管理；当前网站没有这些配置 | 等真实投稿规模需要时再评估，不作为首批投稿的前置条件 |
| 作者提供 HTTPS 媒体地址 | 作者保留文件控制权；本站直接加载，失效时回退分析卡；公开地址和授权需人工核对 | 本次采用。也可由作者在 GitHub 投稿编辑器上传文件，再粘贴 GitHub 生成的地址 |

依据：[GitHub 附件](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files) 支持在 Issue 编辑器上传图片、视频并生成地址，公开仓库附件可公开访问；[Blob 客户端上传](https://vercel.com/docs/vercel-blob/client-upload) 需要存储和服务端授权流程。本次不指定第三方价格、账户套餐或文件额度。

## 契约与流程

1. `/submit` 的中英文表单收作品、图片/视频地址（视频需封面）、替代文本、作者署名与链接、授权人身份依据、授权日期和撤下方式。授权只覆盖本站作品流及详情展示；不包含下载、代码复用、MCP、再分发或商业使用。
2. 表单在浏览器生成可检查的投稿 JSON 和 GitHub 正文。输入不写本地持久化、不发到服务器；复制/下载失败保留文本。作者主动打开 GitHub、粘贴并提交；有本地文件可在 GitHub 编辑器上传。页面不声称投稿已经发送。
3. 维护者核对原作、身份与授权、媒体格式/尺寸/替代文本、署名，补编辑笔记和翻译状态。受控登记保存授权证据与审核者/日期；缺证据的输入不可进入发布数据。新的机器英文标为 draft，生产环境不发布对应英文页面。
4. 公开内容从同一登记派生给客户端和预渲染。授权卡片、详情及参考包指令均写明仅本站展示；媒体来自作者地址，不套用链接预览授权。
5. 撤下先停展示再核实。登记替换成只含稳定 ID、名称、日期、原因的 tombstone；媒体地址不留在当前发布文件或客户端 bundle。原地址显示不加载媒体的撤下说明、不被索引，不列入作品流和 sitemap。已发出的文件、旧提交和外部缓存不能远程收回。
6. 第一版不建设账户、云上传或自动审核，不假设作者投稿自动等于可发布。没有真实投稿时发布登记为空；测试用自有色块媒体和临时记录，不编造作者许可。

## 验收

- 模型/CLI 回归：有效图片和视频；缺授权、证据或审核拒绝；非法地址、重复 ID 拒绝；撤下清除媒体；写前备份及冲突/锁保护。
- 浏览器：双语表单、必填/错误、视频封面、复制失败保留正文、JSON 下载；真实渲染器加载授权图片与视频、可见授权标记和署名；撤下页无媒体请求；draft 英文不进入生产索引。
- 网站完整测试、构建及现有浏览器回归；320/390/1440 截图与无横向溢出检查。
- 不自动向第三方发送投稿，不创建虚假发布记录，不把测试当作真人投稿验收。
