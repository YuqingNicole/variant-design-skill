# PRD-008 · 更新、回退与售后支持

跟踪 Issue：https://github.com/YuqingNicole/variant-design-skill/issues/26

- 优先级：发布必需；状态：待实现。
- 依赖：PRD-005 的权益范围、PRD-006 的可追踪发行及实际安装路径。

## 问题与解决方案

用户买到版本后仍需知道更新期限、兼容性、升级失败怎么办及如何求助。建立可控更新与支持路径，不能依赖开发者手动补发文件，也不能在设计任务期间改写已安装的缓存插件。

## 用户故事

1. 作为购买者，我希望知道当前版本、可领取版本和更新资格。
2. 作为购买者，我希望阅读变更与兼容影响后决定是否升级。
3. 作为购买者，我希望正在进行的项目不会被自动升级打断。
4. 作为购买者，我希望升级失败能回到可用版本。
5. 作为购买者，我希望更新期限结束后仍能使用已取得的本地版本。
6. 作为购买者，我希望再次下载权益允许的旧版本，并知道任何保留限制。
7. 作为购买者，我希望获得可执行支持指引，而不必发送整个代码仓库。
8. 作为维护者，我希望支持记录能关联发行版本、项目类型和脱敏诊断。

## 实现决策

- 根据发行时间与订单固定的权益条款计算可领取范围，边界采用明确时区和比较规则。商业条款未确定前只配置测试权益。
- 检查更新与安装更新分开；联网检查需遵守宿主权限。无网络时本地功能仍可使用。
- 用户主动升级，经已验证的宿主路径安装；不在任务期间自行修改插件缓存。保留兼容的回退发行及说明。
- 项目状态迁移在副本或备份基础上执行；遇到新格式不得由旧版本静默读取后覆盖。回退若不能兼容项目格式，明确提供恢复路径而非假装成功。
- 到期/撤销影响未来受控分发；不远程删除用户成果。旧版本重下载与保留期限必须在购买前说明，不能事后临时决定。
- 支持入口列明故障分类、诊断步骤及联系路径。诊断内容由用户预览后主动提交，默认排除项目源码、环境变量、密钥和授权链接。
- 响应时限、支持期限、退款/争议处理规则需在正式销售前确定；不在当前页面承诺尚无能力兑现的 SLA。

## 验收清单

- [ ] U1：符合资格、到期、撤销及边界日期均返回正确可领取版本。
- [ ] U2：网络或检查更新失败不阻止本地工作，不改变项目文件。
- [ ] U3：升级后宿主识别新版本，已有项目历史和产物仍可用。
- [ ] U4：升级失败可恢复已验证版本，项目格式不兼容时明确拒绝危险写入。
- [ ] U5：购买者在公开条款范围内重新领取旧发行，不需要人工补发。
- [ ] U6：支持诊断默认脱敏，提交前可见，不自动上传整个仓库。
- [ ] U7：支持入口、条款和版本记录从领取页均可访问；商业承诺已确定。

## 测试决策

以测试权益覆盖日期边界、重复领取、撤销、断网；在实际宿主执行升级和回退。用旧/新项目上下文验证迁移恢复，支持流程用脱敏样本验证，不收集真实敏感项目。

## 不在范围内

自动续费、强制更新、远程删除、团队设备管理、24 小时人工支持承诺。

## 完成证据

权益边界结果、真实升级回退记录、上下文兼容结果、支持演练及已发布的服务范围。
