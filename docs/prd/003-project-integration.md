# PRD-003 · 可追踪的项目预览、接入与回滚

跟踪 Issue：https://github.com/YuqingNicole/variant-design-skill/issues/19

- 优先级：P1；执行顺序：3；状态：待实现。
- 依赖：PRD-001 的内容基准、PRD-002 的验证证据。
- 首期范围：原生 HTML 与现有 Vite/React 项目；Next 单独设验证门槛。

## 问题

独立 React 预览刻意不读取原项目 Vite 配置。别名、样式插件、router 和 providers 需要 Agent 临时编写接线；现成 exporter 仅处理本站 hero 配置。用户无法据此确信自己的项目可完整预览、安全接入和回滚。

## 目标与解决方案

用户在真实项目里获得可直接打开的三版预览，选择或指定一版后，将已验证的当前产物接入项目。交付记录列明新建和覆盖文件、检查结果及恢复方式；回滚保护接入之后的用户修改。

## 用户故事

1. 作为项目作者，我希望工具识别现有框架、构建命令、样式和必要 providers。
2. 作为项目作者，我希望 A/B/C 和比较页都能直接打开。
3. 作为项目作者，我希望预览复用我的组件和样式，而非脱离项目的近似展示。
4. 作为项目作者，我希望已有页面、路由和依赖清单不会被意外覆盖。
5. 作为项目作者，我希望指定导出 B 不自动变成选中 B。
6. 作为项目作者，我希望看到接入会改变哪些文件以及对应备份。
7. 作为项目作者，我希望接入后运行项目原有检查并验证真实页面。
8. 作为项目作者，我希望回滚识别我后续的修改，不静默覆盖。
9. 作为项目作者，我希望退出时只清理本次生成且未被修改的预览文件。
10. 作为项目作者，我希望不支持的框架被明确说明，并保留可用候选稿。

## 实现决策

- 先以 HTML 与 Vite 两个真实项目沉淀适配行为，不预设所有框架都必须实现的大型抽象。
- 项目能力记录包含框架/版本、实际构建检查命令、入口、样式/别名/providers 要求；无法识别的事实保持未知。
- 预览与接入共享项目事实。隔离预览不得替换生产入口，不覆盖已有同名路由，不擅自改变现有依赖版本。
- 预览结果包含实际 URL、启动/停止方式、适配文件清单。HTTP 200 不足以证明成功；验证三版身份、关键交互、资源及错误输出。
- 接入记录绑定变体、版本和源内容身份，并记录目标文件集合、接入前内容、接入后内容、创建/覆盖动作、备份与验证结果。
- 应用接入计划前检查源稿与目标基准；出现冲突时停止并保留候选稿。
- 回滚逐项比对接入后基准。用户后来编辑过的文件不自动还原或删除；输出冲突和人工恢复路径。
- 明确失败恢复语义：普通写入失败进行受控恢复；构建失败保留诊断和恢复入口，不输出接入成功。多文件进程中断不宣称全局原子性。
- Next 要等一个真实包含 router/providers 的项目闭环证据后再承诺支持；首期完成不代表 Next 完成。

## 验收清单

- [ ] I1：全新 HTML 项目与已有品牌锁定 Vite 项目各完成生成、三版预览、局部修改、撤回、接入。
- [ ] I2：比较页及 A/B/C 实际打开，关键控件可操作，相关资源加载正常。
- [ ] I3：Vite 项目包含至少一个真实别名、全局样式和 provider 依赖，预览保留其语义。
- [ ] I4：已有同名文件/路由受到保护；记录实际选择的隔离入口。
- [ ] I5：接入后使用项目原有类型检查和构建命令，结果关联当前产物；预存失败单列。
- [ ] I6：指定 B 接入不改变最终选择；A/C 原稿与历史不变。
- [ ] I7：未发生后续修改时可恢复被覆盖文件，并移除本次新建文件。
- [ ] I8：目标在计划后或接入后被用户修改，应用/回滚分别报告冲突且不覆盖用户内容。
- [ ] I9：清理预览不删除原有文件或用户后来改过的适配文件。
- [ ] I10：依赖缺失、不支持框架、检查失败与中断恢复都有可执行说明。

## 测试决策

通过项目级预览/接入/回滚入口，对两个真实小型项目执行完整流程。沿用现有 landing 接入测试的备份、版本和选定状态断言，扩展为通用目标文件验证；用浏览器确认实际页面身份，不只检查 HTTP 状态。真实项目矩阵与安装包执行记录是完成证据。

## 不在范围内

自动部署、任意框架全覆盖、项目依赖大规模升级、Next 支持声明、托管生成平台、自动发布插件。

## 完成证据与跟进

关闭 Issue 前附两个项目矩阵记录、实际预览地址与页面证据、接入清单、检查日志及回滚冲突用例。Next 作为后续独立任务，不得用首期结果代替。
