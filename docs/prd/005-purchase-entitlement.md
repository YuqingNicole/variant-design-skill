# PRD-005 · 购买、权益确认与领取

跟踪 Issue：https://github.com/YuqingNicole/variant-design-skill/issues/23

- 优先级：发布必需；状态：待实现；依赖：PRD-000 商品定义。
- 商业配置未确定前只运行测试交易，不启用真实结账。

## 问题与解决方案

用户付款后没有可信的权益凭证、领取入口或丢失链接后的找回方式。建立服务端确认订单、生成权益并交付可重复访问的领取页面；不能用付款返回页参数证明已经支付。

## 用户故事

1. 作为购买者，我希望付款前确认金额、币种、税费展示、交付内容及使用前提。
2. 作为购买者，我希望支付处理中看到真实状态，而不是误以为失败后重复付款。
3. 作为购买者，我希望成功订单只生成一份有效权益。
4. 作为购买者，我希望验证身份后重新领取自己的版本。
5. 作为购买者，我希望下载链接失效时能重新生成，而不重复购买。
6. 作为购买者，我希望知道退款或争议处理对后续领取的影响。
7. 作为维护者，我希望排查订单而不接触用户项目代码或模型密钥。

## 实现决策

- 订单与权益分开记录；服务端验证支付供应商签名或通过供应商可信查询确认状态，拒绝客户端自行标记付款。
- 重复、延迟、倒序通知必须幂等处理；同一订单不得重复发放，不得因迟到成功事件错误恢复已撤销权益。
- 领取入口通过经验证的购买身份访问；具体身份供应商待选，禁止仅凭猜得到的订单编号下载。
- 权益记录商品、订单、购买身份、状态、可领取发行范围和更新截止规则。时间语义使用服务端标准时间并明确边界。
- 领取页提供当前可领版本、兼容要求、校验信息及支持入口。授权下载链接短期有效；重新领取需再次校验权益。
- 已领取的本地代码和项目不因服务不可用、期限结束或退款被远程删除；撤销仅影响后续受控领取，具体条件由正式政策决定。
- 只收集履行购买所需的信息；不上传代码、模型凭据或完整机器环境。
- 首期复用可靠支付和身份能力，避免自建银行卡处理；供应商选择与政策细节作为开通真实收费的阻断项。

## 验收清单

- [ ] E1：成功测试订单可领取；取消、失败、处理中与伪造返回参数不能领取。
- [ ] E2：重复/倒序通知不会重复发放或错误改变最终权益。
- [ ] E3：其他身份不能访问该订单；过期链接可由合法身份重新生成。
- [ ] E4：重新登录/关闭页面后可找回；邮件通知失败不丢失已确认权益。
- [ ] E5：退款/争议/更新期限边界有明确结果，不删除本地工作。
- [ ] E6：日志不含密钥、授权下载令牌和项目代码。
- [ ] E7：金额、币种、更新期限等未配置时真实结账保持关闭。

## 测试决策

经订单确认与领取入口测试支付事件、身份越权、重复通知、状态恢复和下载过期；使用供应商测试环境。测试应断言权益结果，不以发送邮件次数作为成功标准。

## 不在范围内

自动续费、优惠券体系、团队席位、强 DRM、承诺所有本地副本可被撤销。

## 完成证据

测试订单及状态变化、领取权限测试、失败恢复记录、已选供应商和商业政策。涉及真实支付前需另外明确执行授权。
