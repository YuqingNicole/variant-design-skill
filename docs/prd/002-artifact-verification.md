# PRD-002 · 与产物版本绑定的验证证据

跟踪 Issue：https://github.com/YuqingNicole/variant-design-skill/issues/18

- 优先级：P1；执行顺序：2；状态：待实现。
- 依赖：PRD-001 的版本、文件清单和内容身份；可提前编写负向测试。
- 产品范围：真实项目产物验证；在线工作台复用适用的检查规则。
- 证据基线：master `08d8623`，2026-10-07 临时产物复现。

## 问题

元数据字体锁定为 Georgia，源文件改成 Arial 后仍可应用；这是文档已说明的能力限制。在线 HTML 检查仅看关键词，让移除焦点轮廓的页面得到 11/11。CLI scanner 与在线检查规则不同，而固定 fixture 的测试通过也不能证明新生成的页面符合要求。

## 目标与解决方案

每次交付能说明“验证了哪个产物、验证了什么、哪些仍未知”。静态检查与真实浏览器行为分开记录；产物改变后，旧证据不得继续表示当前产物通过。

## 用户故事

1. 作为项目作者，我希望看到验证对应的变体和版本。
2. 作为项目作者，我希望代码被手动修改后旧验证自动失效。
3. 作为项目作者，我希望字体锁检查实际呈现，而不只检查声明。
4. 作为键盘用户，我希望关键控件具有可见的焦点指示。
5. 作为减少动态效果的用户，我希望 JS 动画也遵守偏好。
6. 作为项目作者，我希望只改 hero 时，其他关键区域的实际行为保持不变。
7. 作为项目作者，我希望工具缺失时显示未验证，而不是通过。
8. 作为项目作者，我希望浏览器失败、项目原有失败和本次新增失败分开报告。
9. 作为交付者，我希望可以交付明确标注未验证的候选稿，但不能把它称为已验收结果。

## 实现决策

- 建立统一的验证证据模块；保留静态 scanner 的诊断价值，提取可共享规则，避免在线检查和 CLI 各自维护相同规则。
- 不使用总分代表上线质量。逐项采用 passed、failed、unverified、not-applicable；后两者必须附原因。
- 记录目标变体、版本、产物文件内容身份、相关共享依赖/品牌约束身份、检查工具与版本、运行条件、时间和检查输出。覆盖范围无法完整追踪时明确标注限制。
- 文件、依赖或约束发生变化时，相关证据失效；撤回即使回到相同内容，也不能未经确认沿用旧运行环境的结论。
- 品牌锁检查关键元素的 computed styles 与约定 token 用法；不宣称自动证明所有 CSS 正确。
- 焦点以实际键盘导航和可见指示为验收依据，允许明确可见的替代轮廓样式；单凭 outline:none 不足以判定所有情况失败。
- 动效检查覆盖初始 reduced-motion 和运行期间切换；局部修改检查包含非目标区域代表性行为和布局。
- 验证失败不得输出“已验收可上线”；无工具时保留候选稿并列出未验证项。是否交付未验证候选稿须显式记录，不能伪造成功。

## 验收清单

- [ ] V1：相同元数据下实际字体漂移，在指定浏览器检查中失败。
- [ ] V2：包含 focus-visible 但无可见指示的关键控件不能获得通过；有可见替代指示的控件按实际表现判定。
- [ ] V3：仅有 reduced-motion CSS、JS 仍运行的案例被运行时检查发现。
- [ ] V4：每条证据能定位变体、版本、内容身份、运行条件与结果。
- [ ] V5：检查通过后修改文件或相关共享依赖，交付流程不再将该证据视为当前有效。
- [ ] V6：缺少浏览器/类型检查工具时显示 unverified，不能折算成通过。
- [ ] V7：局部修改导致非目标区域行为变化时，相关检查失败并给出定位信息。
- [ ] V8：在线检查与 CLI 对共享静态规则给出一致的规则标识与结论；运行时检查单独呈现。
- [ ] V9：在一个真实生成产物上运行完整检查，记录预存失败与本次新增失败。

## 测试决策

从产物验证入口输入正反例，断言输出结论、覆盖范围和证据失效，而非正则实现。复用已有实际 React 预览、键盘焦点和 coffee reduced-motion 回归；新增字体漂移、焦点替代样式和证据过期用例。固定 fixture 证明机制，真实产物记录证明本次交付，两者不可互相替代。

## 不在范围内

审美自动评分、转化率预测、全站无障碍认证、任意 CSS 的形式化证明、取消人工设计评审。

## 完成证据与跟进

关闭 Issue 前附验证报告样例、真实产物身份、负向用例结果、原有检查兼容结果和未验证项。PRD-003 使用此证据模型记录接入前后检查。
