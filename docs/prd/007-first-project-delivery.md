# PRD-007 · 首次项目交付引导

跟踪 Issue：https://github.com/YuqingNicole/variant-design-skill/issues/25

- 优先级：发布必需；状态：待实现。
- 依赖：PRD-006 的可用安装；PRD-001～003 的冲突保护、验证与项目接入。


架构前置：[RFC-001 · 基于用户项目的设计与交付工作流](../rfc/001-project-aware-design-workflow.md)。先完成只读项目识别，保留来源证据与未知，再据此生成任务单和适配计划。识别结果不能替代实际写入前的基准检查。

## 问题与解决方案

安装不是用户的目标。用户需要在自己的项目里看见三种方案、选择、放心修改，最后取得可运行的实际代码。把首次使用组织成有阶段、有产物、有恢复点的项目旅程。

## 用户故事

1. 作为首次用户，我希望一句请求即可启动项目检查，不需要先懂命令。
2. 作为项目作者，我希望工具复述本轮页面范围、核心任务和品牌约束。
3. 作为项目作者，我希望方案共享数据与必要功能，能公平比较。
4. 作为项目作者，我希望了解各方案优化、牺牲和适用场景。
5. 作为项目作者，我希望试改 B 不自动选定 B。
6. 作为项目作者，我希望撤回和恢复在第一次使用时就可理解。
7. 作为项目作者，我希望接入前看见将变更的文件，接入后看到运行结果。
8. 作为项目作者，我希望会话中断后能继续，不重复覆盖项目。

## 实现决策

- 首次任务在用户实际项目执行，不要求先使用在线工作台或复制官网示例。
- 只读识别项目事实，输出简短任务单：目标、页面范围、共享核心任务/数据/功能、品牌约束、适配路径与验收方式。缺失会影响结果的信息才询问，遵守现有最多两个关键澄清问题约束。
- 不支持的项目在写入前说明；允许保留任务单和候选设计，但不能承诺完成接入。
- 阶段依次为检查项目、确认任务、生成候选、比较、修改/撤回、指定接入、验证交付。编辑与选择分别记录，中断恢复读取真实文件和历史。
- 每阶段结果可追踪到当前产物版本；模型失败、预览失败或检查失败不跳到完成。
- 接入沿用用户已授权范围，不机械增加逐步确认；超出已确认的修改范围时说明新增影响。
- 交付摘要提供实际代码位置、运行方式、当前版本、验证结果与恢复入口，不用主观审美分数替代功能证据。

## 验收清单

- [ ] F1：首次用户在已有 HTML 和品牌锁定 Vite 项目中分别完成整个闭环。
- [ ] F2：三版共享核心任务、数据和必要功能，并有可打开预览及取舍说明。
- [ ] F3：只改 B hero、撤回、重新修改不影响 A/C 或最终选择。
- [ ] F4：不支持/缺失依赖/模型失败等路径明确停在哪一阶段，能安全继续。
- [ ] F5：会话中断后恢复真实状态，不重复应用或误报完成。
- [ ] F6：最终接入包含验证记录与恢复入口，未验证内容不冒充通过。
- [ ] F7：至少两位未参与开发的试用者参与，记录任务完成、求助、卡点与修改动作；不把样本当作转化率结论。

- [ ] 新增：按 RFC-001 核对目标入口、品牌、必要行为、共享依赖及已有修改；未知项不被伪装成支持。
- [ ] 新增：任务单、选择理由、修改凭证与交付摘要关联同一任务/版本；识别过期后先刷新再继续。

## 测试决策

经安装后的用户入口和真实项目执行，采集产物身份、预览、变更及恢复证据。复用内核验收而不重复实现另一套历史；手工可用性观察补充自动测试，项目代码不默认上传。

## 不在范围内

支持任意技术栈、保证审美或商业转化、替用户部署、把人为救场伪装成自动完成。

## 完成证据

两条完整项目记录、冷启动观察、失败恢复记录和仍需人工协助的事项。未完成依赖时不关闭本 Issue。
