# PRD-000 · 付费产品形态与购买后完整旅程

跟踪 Issue：https://github.com/YuqingNicole/variant-design-skill/issues/22

- 优先级：发布前置；状态：需求基线已记录，产品未实现、未开放销售。
- 目标：用户购买后独立完成领取、安装、第一次项目交付和后续升级。
- 定义关系：统领 PRD-005～008 的交付路径及 PRD-001～003 的项目可靠性；PRD-004 是独立在线演示，不是付款后的必经步骤。

## 问题

目前有公开 skill、可构建的插件 RC、官网 pricing 和案例，但没有购买权益、领取、安装验证及升级闭环。用户还不能凭付款获得明确且可独立使用的 Pro 产品。

## 产品定义

交付形态为在用户本地代码项目中运行的 Variant Design Pro 插件发行包，包含完整技能目录、项目预览/接入辅助工具、经过验证的适配、使用文档与原创示例。它通过用户自己的 Codex 环境运行；官网负责介绍、购买、领取和支持，不另建必须登录的设计编辑器。

首期一个个人使用的 Pro 商品，优先服务准备发布 HTML 或 Vite/React 产品的独立开发者。Next 不承诺首期支持。首期不承诺人工代做、无限模型调用或团队管理。

用户最终获得：可安装发行包、版本与兼容说明、权益凭证、更新领取入口；每个项目工作中获得任务单、A/B/C 可运行预览、选择理由、局部修改历史、接入清单、验证记录与恢复方式。

## 用户故事

1. 作为购买者，我希望付款前知道买到什么、哪些不包含及需要什么环境。
2. 作为购买者，我希望付款后有明确领取入口，关闭页面后还能找回。
3. 作为购买者，我希望安装后能确认插件确实被 Codex 识别。
4. 作为购买者，我希望在自己的项目中完成第一次三版比较和代码接入。
5. 作为购买者，我希望模型成本、更新期限与支持范围事先说明。
6. 作为购买者，我希望更新期限结束后既有项目和已取得版本仍可使用。
7. 作为开源用户，我希望现有公开代码不会被重新描述成独占付费能力。

## 免费与 Pro 的边界

公开 skill 继续按现有许可提供，不收回既有权利。P0 冲突修复等保护用户代码的基础安全修复不作为付费门槛。

Pro 候选增量是维护过的发行体验、经过项目矩阵验证的适配、原创示例/流程资源及明确范围的更新支持。现有公开功能不因换包装而成为独占能力。每个付费承诺必须有实际资产、演示和验收证据；尚未形成足够增量时只做封闭试用，不开放收费。

外部灵感截图、链接和第三方模板不计入“原创付费资源”。现有 MIT 内容保留许可；新增资源的权利、再分发条件在采用前单独确认。

## 商业基线与待定决策

采用“购买当前发行版本，并包含明确期限内更新”的方案作为设计基线；暂不实现自动续费。当前未确定价格、更新期限长度、收款主体、支付供应商、退款规则及支持承诺。实施领取与安装原型不依赖这些值，但正式结账必须等它们完成并一致展示。

模型使用资格和消耗由用户的宿主环境承担；商品不得暗示包含 Codex 订阅或无限额度。具体平台安装/分发能力需实测，不把目录付费、激活码或自动安装当成已存在的平台能力。

## 端到端旅程

价格与兼容说明 → 结账 → 经服务端确认付款 → 身份验证与领取 → 下载有版本的完整包 → 按已验证方式安装 → 宿主识别确认 → 读取项目 → 确认任务单 → 三版预览 → 局部修改/撤回 → 指定方案接入 → 项目检查 → 交付记录。

安装失败返回诊断与支持；不支持的项目在生成前说明；接入失败保留原项目及候选稿；关闭浏览器不丢失购买权益。

## 验收清单

- [ ] J1：商品页、结账、领取页、发行包与支持说明对交付内容一致。
- [ ] J2：每项付费增量可展示实际资产与相对公开版的价值；无虚构能力。
- [ ] J3：PRD-005、006、007、008 对应的发布必需验收完成。
- [ ] J4：至少两位未参与开发的试用者各完成一次旅程，覆盖 HTML 与 Vite 项目；记录帮助次数及卡点，不冒充统计结论。
- [ ] J5：首轮封闭测试使用测试订单，不提前收真实款来验证未完成路径。
- [ ] J6：安装资格、模型成本、支持范围、更新期限与恢复方式在付款前可见。
- [ ] J7：待定商业字段和平台分发验证没有悬空项后才允许开放收费。

## 测试决策

从测试结账开始走真实安装与本地项目交付，分别记录交易证明、发行版本、项目检查与用户帮助点。支付模拟不能代替真实安装测试，打包解压不能代替宿主发现，官网案例不能代替用户项目交付。

## 不在范围内

本 PRD 不启动真实收费、注册支付账户、提交市场审核或发布插件；不建设云端模型平台、团队席位和自动续费。
