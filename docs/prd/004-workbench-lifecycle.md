# PRD-004 · 在线工作台的异步状态与持久化一致性

跟踪 Issue：https://github.com/YuqingNicole/variant-design-skill/issues/20

- 优先级：P2；执行顺序：4；状态：待实现。
- 产品范围：在线工作台；不等同已安装 skill 的文件历史。
- 依赖：实现可独立开展；沿用前述版本/验证语义，不要求共用同一存储实现。
- 证据：master `08d8623` 静态代码路径确认；异步竞态尚待浏览器复现。

## 问题

生成或迭代期间仍可恢复历史，迟到结果使用请求前的 directions 写回，可能覆盖恢复结果，并与已恢复的 brief 不一致。历史加载只确认 JSON 为数组；损坏记录可能导致渲染失败。界面在持久化成功前提示版本已保存，存储失败没有明确恢复提示。

## 目标与解决方案

工作台中的 brief、A/B/C、当前方向和历史始终属于同一个有效状态。恢复或开始新操作后，旧请求不能再修改当前状态。用户清楚区分内存中的修改与已持久化的历史。

## 用户故事

1. 作为使用者，我希望恢复旧版本后不会被迟到的生成结果覆盖。
2. 作为使用者，我希望取消或过期请求的成功、失败消息都不干扰当前任务。
3. 作为使用者，我希望 brief、方向和版本记录保持一致。
4. 作为使用者，我希望失败后仍能使用之前有效的工作区。
5. 作为使用者，我希望存储失败时收到准确提示，而不是已保存。
6. 作为使用者，我希望重新打开页面时能恢复有效历史。
7. 作为使用者，我希望损坏历史不导致整个工作台无法打开。
8. 作为使用者，我希望浏览/编辑方向与最终选择语义明确，不默认替我选定赢家。
9. 作为使用者，我希望模型调用测试无需真实账户或付费调用。

## 实现决策

- 将异步结果归属、恢复、方向浏览/编辑及历史保存集中到工作台生命周期模块，React 负责呈现。
- 每次请求带工作区身份或等价归属信息；恢复使旧请求失效。能取消则取消，但即使取消失败，迟到结果也必须被忽略。
- 成功、失败及 finally 清理都受请求归属约束，旧请求不得关闭新请求的 busy 状态或覆盖错误提示。
- 恢复允许在请求期间使用；恢复动作明确中止该请求对当前工作区的影响，不仅临时禁用按钮。
- 集中校验持久化记录的结构、日期、方向集合和支持的格式版本；损坏记录不直接进入渲染。
- 保留现有最多 12 条历史的容量策略，存储错误不得无提示清空有效历史。无法持久化时保留内存状态并提示重新尝试或导出。
- 只有持久化成功后显示“已保存”；显示上区分当前方向与明确最终选择。旧字段含义不明时按浏览/编辑状态迁移，不能推断赢家。
- 不强行统一浏览器 HTML 快照与插件文件事务。两者共享产品语义，保留不同的存储方式和能力范围。

## 验收清单

- [ ] W1：先在浏览器复现 pending build 后恢复历史被覆盖的路径，保存失败用例。
- [ ] W2：build、iterate、generate 的迟到结果在恢复后均不能覆盖当前工作区。
- [ ] W3：旧请求失败或结束，不改变后发请求的 busy/error 状态。
- [ ] W4：失败保留之前有效的 brief、方向与历史；恢复后所有字段属于同一版本。
- [ ] W5：存储拒绝或容量不足时不显示已保存，内存工作仍可继续和导出。
- [ ] W6：损坏 JSON、无效日期、缺失方向及未知格式不会导致白屏，提供明确恢复提示。
- [ ] W7：有效历史重载可用，容量规则保留；不把已有浏览方向迁移成最终赢家。
- [ ] W8：现有选择、导出、双语与手机预览流程无回归。

## 测试决策

优先通过浏览器操作和可控延迟的模型响应验证竞态，覆盖成功、失败、取消失败和倒序返回。用可控存储失败验证真实提示与恢复；不依赖真实模型凭证。生命周期模块测试行为，避免测试 React 内部状态字段或 helper 调用次数。既有网站案例演示撤回测试不能替代工作台历史测试。

## 不在范围内

多标签实时同步、云账号、数据库、模型质量升级、全面重写官网、将在线工作台作为插件主内核。
