# references/voice.md · 反 AI 味写作规范

把审美和语言感写进规则。每条都有对应的真实教训。用于中文内容创作、公众号文章、产品文案。

---

## 语言指纹

**短句。** 一个意思，停。

**场景开头，不用背景开场。** 不是"今天我想聊聊X"

**先说观点，再展开。** 不是"有人认为A，也有人认为B"

**具体不模糊。** "凌晨一点，茶凉了" 不是 "很晚的时候"

**每句话都有信息量。** 没有填充句。

---

## 禁用开场白

| ❌ 禁止 |
|---------|
| "在当今时代……" |
| "随着……的发展……" |
| "不可否认的是……" |
| "值得注意的是……" |
| "总的来说……" / "综上所述……" |
| "作为一个X，我深刻体会到……" |
| "首先……其次……最后……"（列表伪装成散文） |

---

## 禁用词（AI 味）

```
深刻 / 全面 / 系统性 / 赋能 / 落地 / 闭环 / 生态
颠覆性 / 革命性 / 划时代 / 探索 / 解读 / 剖析
干货 / 硬核 / 有效 / 赋予 / 构建 / 深入浅出
```

## 文体分类与结构模式

不同文体有不同的骨架。写之前先确认文体，再套结构。

### 观点文（我认为 X，因为 Y）

**骨架：**
1. 挑衅句 — 让大多数人想反驳的一句话
2. 反直觉的证据 — 一个具体案例打破预期
3. 真实原因 — 不是表面的，是背后的机制
4. 余韵 — 不总结，留一个开放问题或意象

**忌：** 正反两方都说，最后"所以要综合考虑"

**例子骨架：**
```
好的设计不需要解释。（挑衅）
但我见过最难用的产品，设计团队里有三个获过奖的设计师。（打破预期）
问题不在设计能力，在他们从来不坐在用户旁边看用户怎么用。（真实原因）
能力和观察，是两件事。（余韵）
```

---

### 故事文（发生了什么，然后呢）

**骨架：**
1. 场景锚点 — 时间 + 地点 + 一个感官细节
2. 事件转折 — 预期被打破的那一刻
3. 内部反应 — 不是"我很震惊"，是具体的想法或行动
4. 落地意义 — 这件事说明了什么（一句话，不展开）

**忌：** 故事讲完了还要加"这让我明白了一个道理……"

**例子骨架：**
```
凌晨一点，茶凉了，屏幕上是第七版配色方案。（场景）
客户说"感觉不对"。没有更多解释。（转折）
我把所有方案删掉，重新问了一个问题：他们的用户是谁？（内部反应）
对的问题比对的答案更值钱。（落地意义，就这一句）
```

---

### 教程文（如何做 X）

**骨架：**
1. 问题前置 — 这个教程解决什么具体问题（不是"今天教大家"）
2. 步骤极简 — 每步一个动作，动词开头
3. 反例先行 — 每个关键步骤给一个"这样做是错的"
4. 边界说明 — 这个方法在什么情况下不适用

**忌：** 每步都有三句铺垫再说动作；结尾"希望对你有帮助"

**例子骨架：**
```
你的表单提交率低，大概率是这一个问题。（问题前置）
1. 把"提交"改成具体动词 + 对象。（步骤）
   ❌ "提交" ✅ "创建账户" / "发送申请"
2. 把必填字段砍到最少。（步骤）
   问自己：这个字段如果不填，流程会断吗？
这个方法对表单不长的情况有效。复杂多步表单另说。（边界）
```

---

### 产品文案（让用户做一件事）

**骨架：**
1. 价值主张 — 用户得到什么（不是产品有什么功能）
2. 消除阻力 — 用户最大的顾虑是什么，正面回应它
3. 单一行动 — 一个 CTA，动词 + 对象，不超过 5 个字

**忌：** 一段文案里塞三个卖点；CTA 写"了解更多"

**例子：**
```
❌ 我们的AI设计工具功能强大，支持多种输出格式，帮助设计师提升效率。立即体验！
✅ 输入一句话，3 秒拿到 3 个可用的设计方向。不需要会设计。
   [开始生成]
```

## 平台语气差异

### 公众号（深度阅读场景）

- 句子可以稍长，有节奏感
- 允许情绪，但情绪要有来源（不是"感动"，是"那一刻我想起了"）
- 结尾留余韵，不呼吁转发
- 段落间距大，每段不超过 4 句

### 小红书（扫描式阅读场景）

- 首行必须是"钩子"：数字 / 反常识 / 强体验词
- 大量换行，一句一行
- emoji 用于分段和强调，不滥用
- 结尾用问题引评论（但问题要具体，不是"你怎么看"）

**小红书首行公式：**
```
[数字] + [反常识结论]
[我/亲测] + [具体结果]
[别再] + [常见错误]
```

**例子：**
```
公众号版：
那天快零点了。桌上的茶早凉了，我还在盯着屏幕——给一个新项目选颜色。
颜色都挺好看的，但就是感觉不对。

小红书版：
选了 3 小时颜色，最后用了第一个方案
因为那个时候我还没想清楚：这个品牌到底想让人感受到什么
你选颜色的时候有没有卡在这里？
```

### 产品内文案（任务场景）

- 极简，能用 5 个字说清楚就不用 10 个
- 按钮文字 = 动词 + 对象（"保存草稿"不是"确认"）
- 错误提示 = 出了什么问题 + 怎么修（不是"操作失败"）
- 空状态 = 这里将会有什么 + 怎么开始（不是"暂无数据"）

## Before / After 对比

### 宏大背景 → 具体场景

❌ **AI 味：**
> 在当今人工智能飞速发展的时代，越来越多的企业开始意识到品牌设计的重要性。作为一名创业者，我深刻体会到，一套好的视觉系统对于品牌建设具有不可忽视的作用。

✅ **人味：**
> 那天快零点了。桌上的茶早凉了，我还在盯着屏幕——给一个新项目选颜色。颜色都挺好看的，但就是感觉不对。

---

### 文化引用 → 直接切入

❌ **AI 味：**
> 五行理论作为中国传统文化的重要组成部分，蕴含着古人对自然规律的深刻理解。将其应用于现代品牌设计，不仅能够体现文化自信，也能够为品牌注入独特的东方美学韵味。

✅ **人味：**
> 青赤黄白黑。这套颜色体系，比潘通早了两千年。

---

### 总结段 → 留余韵

❌ **AI 味：**
> 综上所述，五行配色系统为我们提供了一套系统化的颜色选择框架。希望本文能够对大家的品牌设计工作有所启发。你在品牌设计中有哪些心得？欢迎在评论区分享！

✅ **人味：**
> 颜色是表面，但选颜色这件事逼着你想清楚：我是谁，我想让人感受到什么。那天凌晨一点选完颜色，我觉得自己终于想清楚了这个问题。

---

### 功能说明 → 一句话

❌ **AI 味：**
> Skill 是一种模块化的知识包，它能够帮助 AI 系统更好地理解特定领域的知识，从而提升其在相关任务中的表现。通过合理设计 Skill，我们可以实现 AI 能力的定向增强。

✅ **人味：**
> 一个 skill 就是一个文件。AI 读到它，相当于接受了一次专业培训。把规则写死，AI 就不会乱来了。

---

### 产品文案 → 以用户为主语

❌ **AI 味：**
> 本产品支持多种设计风格输出，提供专业级别的设计方案，助力您的项目快速落地。

✅ **人味：**
> 说出你想要什么，3 秒后你有 3 个可以直接改的方案。

## 改写规律总结

| AI 套路 | 人味替换 |
|---------|---------|
| 宏大时代背景开场 | 具体场景，一个细节 |
| "深刻体会到" | 直接说那个体会 |
| 三段论结构 | 一个观点 + 一个证据 + 一个余韵 |
| "综上所述" | 删掉，直接结尾 |
| 反问+邀请评论 | 留一个开放问题，不求互动 |
| 修饰词堆叠 | 一个动词，一个名词 |
| "不可否认……有人认为A，也有人认为B" | 选一边，说清楚你的立场 |
| 以产品为主语 | 以用户为主语，说用户得到什么 |
| 平铺直叙列功能 | 一个场景 + 一个结果 |

---

## 结尾原则

好的结尾不是总结，是**余韵**。

选一种：
- 一个开放的问题（不是"欢迎分享"那种）
- 一个意象或细节，让读者自己想
- 一句让人觉得"对，就是这样"的话
- 把开头的场景接回来（首尾呼应，不重复）

不要：
- 再次总结全文要点
- 呼吁转发、点赞
- "希望本文对你有帮助"
- "如有不足，欢迎指正"

## 写作流程（Claude 执行时）

用户触发写作模式（"帮我写一篇公众号文章"、"写产品文案"、"去AI味"等）时：

1. **确认文体** — 观点文 / 故事文 / 教程文 / 产品文案？
2. **确认平台** — 公众号 / 小红书 / 产品内？
3. **确认核心信息** — 一句话：这篇文章要让读者记住什么？
4. **套骨架** — 从本文件的文体分类选对应骨架
5. **写初稿** — 用语言指纹检查每句话
6. **过滤检查** — 逐句对照禁用词和禁用开场白
7. **改写输出** — 如果是"去AI味"任务，先引用原文，再输出改写版，最后说明改了什么

**去AI味任务的输出格式：**
```
原文：[引用]

改写：[人味版本]

改了什么：[1-2句，说核心改动]
```
